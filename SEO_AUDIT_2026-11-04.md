# easybacnet.com: SEO audit (2026-11-04)

Scope: the whole site after the points library grew from 328 to 560 model pages (100 manufacturers) and the new guide `find-bacnet-points-list-for-your-equipment` went in. 720 sitemap URLs: home, privacy, terms, 1 tool, 39 guides, plus 678 library pages (hub, 100 manufacturer pages, 4 gateway-only brand pages, 13 equipment categories, 560 models).
How it was checked: a stdlib Python checker ran over every local page listed in the sitemap. It looked at title and description, canonical and og:url against the sitemap `<loc>`, H1 count, alt text and image size attributes, JSON-LD parsing and the Dataset fields, internal links (with anchors), inbound links and click depth from home, and HTML size. A 5-word-shingle near-duplicate pass compared main content only, leaving out the nav, footer, scripts and the sibling-card grid. Live checks used curl against https://easybacnet.com. 50 random sitemap URLs were tested, plus redirect, compression and bot-UA probes. One heavy page was measured in a browser at 375 px. The PageSpeed Insights API quota was used up, so there is no Lighthouse score.
Settled decisions from the 09-25 and 09-30 audits were not reopened: FAQPage stays, the `export-bacnet-points-to-csv` slug stays, and the PC app is not mentioned.

## What is healthy

- **Live = local.** The live sitemap had the same 715 URLs as the local build when checked (the local build is now 720 because the other agent added guides). 50/50 sampled URLs return 200 with 0 redirects. `.html` and `/index.html` URLs 308 to the clean URL in one hop. Model pages with a trailing slash 308 to the no-slash form, and directory pages without a slash 308 to the slash form. http and www both 301 to the https apex. There are no chains. `/nonexistent` returns a real 404.
- **Canonicals and URLs.** All 720 pages have exactly one self-referencing canonical, and it equals the sitemap `<loc>` and `og:url`. Internal hrefs are all in clean form (no `.html`, and no directory links without the slash). There are 0 broken links and 0 broken `#anchors`.
- **Titles and descriptions.** No duplicate titles and no duplicate descriptions across 720 pages. The `_full_title` collision logic works. Every model title leads with "<Manufacturer> <Model> BACnet Points List".
- **Headings and markup.** Exactly one H1 per page. Every `<img>` has `alt`. All JSON-LD blocks parse.
- **Internal linking.** There are no orphans. Every page is at most 2 clicks from home: 61 pages at depth 1 and 658 at depth 2. Home links the hub, 8 popular lists and 11 of the 13 categories. 38 of 39 guides link into the library, and every model page links two guides.
- **Crawling and access.** Googlebot, Bingbot, GPTBot, ClaudeBot and PerplexityBot UAs all get 200. robots.txt is `Allow: /` plus the Sitemap line. The IndexNow key file is live. HTML is served Brotli-compressed.
- **Page weight is acceptable.** The heaviest model (Swegon GOLD E, 721 KB raw) transfers as 65 KB. The hub is 873 KB raw and 105 KB on the wire. The 1,049-object Carrier SmartVu is 497 KB raw and 52 KB on the wire. At 375 px there is no horizontal scroll, the filter runs in about 2 ms, and CLS is 0 (measured on the Swegon page in a hidden browser pane, so treat it as indicative). Everything is far below Google's 15 MB HTML indexing limit.

## Fixed in this pass (points_library.py only; output regenerated with `python build_site.py`)

1. **HIGH: library freshness dates were false.** Every library page said "Updated 28 October 2026" and `dateModified: 2026-10-28`, including the 232 pages first published on 4 November. The EDE `TIMESTAMP_OF_LAST_CHANGE` had the same problem.
   Fix: `data_dates()` and `assign_dates()` read each data file's first and last commit date from git, using one `git log` plus one `git status` call. A file that is untracked or modified counts as changed today. A page's date is `max(UPDATED, last commit)`, so `UPDATED` now works as a *template floor*: bump it only when the templates change meaningfully for every list. Hub, manufacturer, brand and category pages use the newest date among their models (`newest()`). Model pages now also get a Dataset `datePublished`. If git is unavailable, every page falls back to `UPDATED`.
   Result: 341 pages show 28 Oct, 36 show 29 Oct, and 301 show 4 Nov.
   New: `points_library.LASTMOD`, a dict `{relpath: ISO date}` covering every library page, ready for the sitemap (see B1).
2. **MED: doubled brand names on 18 models**, for example "Berner Berner AIR air curtain", "Condair Condair RS" and "Setra Setra FLEX". They appeared in the H1, Dataset name, Product name, keywords, FAQ questions, H2s, cards, table captions, aria-labels, CSV header and EDE project name.
   Fix: new `model_rest()` and `full_name()`, now used everywhere those strings were built.
3. **LOW: the four gateway-only brand pages (Hitachi, Midea, MHI, Panasonic) had 1 inbound link each.** The fix is a "Brands covered" facts row on the 19 gateway model pages (Intesis, CoolAutomation and others), linking each covered brand to its page. All 11 link targets exist. The least-linked library pages now have 2 inbound links.

The checker was re-run after the rebuild: 720/720 canonicals OK, 0 broken links, 0 JSON-LD parse errors, and 0 doubled names.

## Needs build_site.py changes (not made: another agent is editing it)

### B1. HIGH: sitemap `<lastmod>` is a single false date for all 720 URLs
Every `<lastmod>` is `2026-10-11` (`UPDATED` in build_site.py, line 40). That date is older than 678 of the pages. Google uses lastmod only when it is "consistently and verifiably accurate", so today it is almost certainly ignored for the whole site. Bing leans on lastmod more heavily.
Fix in `main()`, in the sitemap loop:
```python
for u in urls:
    lm = points_library.LASTMOD.get(u, UPDATED)
    sm.append("  <url><loc>%s/%s</loc><lastmod>%s</lastmod></url>" % (BASE_URL, u, lm))
```
For guides, add per-guide `updated=` (and `published=`) keys to each `GUIDES` entry and use `g.get("updated", UPDATED)`. This was first recommended on 09-25 and is still open.

### B2. MED: guide dates are wrong, and the new guide claims it was published before it existed
`find-bacnet-points-list-for-your-equipment` (added 4 Nov) has `datePublished: 2026-10-11` in both FAQPage and Article, and shows "Updated 11 October 2026".
Fix in `page()` (around line 236): take `published` and `updated` from the guide dict. Set `datePublished` to `published` and `dateModified` to `updated`, and use `updated` for the visible line. The new guide should be `published="2026-11-04"`. Guides the other agent is editing today should get `updated="2026-11-04"`.

### B3. MED: `Article.mainEntityOfPage` points at a redirecting `.html` URL (38 guides)
`"mainEntityOfPage": "%(base)s/%(slug)s.html"` at line 268 is not caught by `_clean_internal_urls()`, which only rewrites `href`, og:url, `"item"` and `<loc>`. Fix: change it to `"%(base)s/%(slug)s"`. While there, add `"description"` to the Article node. The breadcrumb `"item": ... .html` values in the same template are already cleaned at write time, so they are fine.

### B4. MED: keyword cannibalisation between two guides
`how-to-find-your-bacnet-points-list` ("How do I find my BACnet IP points list?") and the new `find-bacnet-points-list-for-your-equipment` ("Find the BACnet Points List for Your Equipment") target almost the same query. A third page, `how-to-use-easy-bacnet`, is titled "How to Scan for Your BACnet Points List". The bodies do differ: the first covers five ways to get *your building's* list, the second covers the *manufacturer's* list for a model. Only the titles blur them.
Fix: retitle the new guide around its real angle, for example `title="Find a Manufacturer's BACnet Points List by Model | Easy BACnet"` (57 chars), with an H1 and question to match. Keep the reciprocal links that already exist. Do not merge the two pages.

### B5. LOW: home page category row is missing 2 of 13 categories
`Thermostats, sensors & meters` (59 models) and `Other equipment` (20 models) are not linked from home (INDEX, around line 4372). Add:
`&middot; <a href="bacnet-points-lists/equipment/sensors-thermostats/index.html">Sensors &amp; meters</a>`

### B6. LOW: carried over from earlier audits
- `Organization` has no `sameAs`. Add the Play listing and https://easymodbus.com.
- `SoftwareApplication` (home) has no `installUrl`/`downloadUrl`, even though the app is live on Play. Add `"installUrl": "https://play.google.com/store/apps/details?id=com.easybacnet.app"`.
- `read-bacnet-values-from-phone` has 4 screenshots without `width`/`height` (CLS risk). The `screenshot_block()` path sets them; this guide builds its images some other way.
- `404.html` uses a relative favicon (`href="icon.svg"`), which breaks on deep 404s. Change it to `/icon.svg`.
- `terms.html` description is 108 chars. Leave it (legal page).
- IndexNow: `--ping` submits all 720 URLs every time. Bing's guidance is to submit only changed URLs. Once B1 is in, ping only URLs whose lastmod is today:
  `ping_indexnow([u for u in clean if lastmod_for(u) == today])`.
- llms.txt is 112 KB, because it lists 560 model lines. That is acceptable. Optionally keep llms.txt to the hub, categories and manufacturers, and move the model lines to `llms-full.txt` (the catalogue is already at `/bacnet-points-lists/index.json`).

## Decisions for Tim

### T1. MED: Dataset `license` is missing on all 560 Datasets
Google's Dataset docs list only `name` and `description` as required, so this does not stop eligibility. `license` is recommended, though, and Dataset Search shows it and filters on it. GSC will report "Missing field license" as a non-critical issue on 560 items.
The points themselves are facts re-typed from manufacturer documents. What you can license is your own compilation: the table layout, the descriptions and the integration notes. Options:
- (a) CC BY 4.0: add `"license": "https://creativecommons.org/licenses/by/4.0/"` in `model_page()` and to the `DataCatalog` in `hub_page()`.
- (b) Point `license` to a short "Use of this data" section on /terms.
This is a one-line change once you choose. It was not made because it is a legal choice.

### T2. LOW: `about: Product` inside each Dataset
Google's Product-snippet parser can pick up nested `Product` nodes and flag them for missing `offers`/`review`/`aggregateRating`. Check GSC > Enhancements for a "Product snippets" report. If 560 invalid items show up, change the node in `model_page()` to `{"@type": "Thing", "name": full_name(m)}` and move the brand to `keywords`. Invalid items do not hurt rankings; they only add noise in GSC.

### T3. LOW: E-E-A-T
There is still no /about page. The library already does several things right: it attributes sources, names the document number and revision for each list, links the source with `rel=nofollow`, has an error and removal contact, and states that it is not affiliated with any manufacturer. A one-paragraph /about saying who maintains the lists, how they are re-typed and verified, and how to report an error would close the gap. It should be linked from the library footer and referenced as the Organization `url`/`publishingPrinciples`.

## Leave alone (checked and decided)

- **Thin pages.** The smallest list is 4 objects (Melink IH4 virtual output module), and 36 models have fewer than 20 objects. Even so, every model page has 966 or more words of main content, with 600+ shingles that appear on no other page: the summary, integration notes, minimum points, facts and FAQ. Berner WCA (11 objects) and the Trane sensor subsets are fine. **No noindex.** The only candidate worth thinking about is merging the 4 Melink IH4 sub-device pages (4-8 objects each) into one "Melink Intelli-Hood IH4" page with 301s. That is optional and is a data and structure decision.
- **Near-duplicate siblings.** 18 pairs score 0.80 or higher on main-content similarity: Siemens PTEC series vs parallel fan (6524/6526, 6624/6626, 6625/6627), JCI VAV1717/1732 apps, Carrier 62H/62X DOAS, Carrier SystemVu FE/GE vs FEQ/GEQ, and Laars MagnaTherm/OmniTherm. Each is a distinct, separately searched controller application with a different object set, so **keep them all indexed and self-canonical**. The best extra protection is unique text on each page. One useful future addition for `model_page()`: a computed "How this differs from <closest sibling>" box that lists the objects present in only one of the two. That is a template feature, not a fix, so it was not done here.
- **FAQPage on 598 pages.** Since 2023 Google shows FAQ rich results only on authoritative government and health sites. The markup is harmless, Bing and AI answer engines still read it, and the 09-30 audit decided to keep it. Keep.
- **Page weight.** 77 pages are over 200 KB raw, and the Swegon page has about 19k DOM nodes. On the wire they are 50-105 KB, and the table *is* the content. Don't paginate or lazy-render (that would break `#obj-` anchors and Ctrl+F). Watch GSC > Core Web Vitals once CrUX data exists. If the hub shows poor mobile LCP or INP, consider shipping its 560-row "Every model" table via `index.json` instead of inline HTML.
- `?q=` written by the filter through `replaceState`: the canonical covers it.
- hreflang: not applicable (English only).
- The `/guides/` → `/#guides` 301 and the 7 removed-guide 301s in `_redirects` are all single-hop, and none of them are in the sitemap.
- Sitemap size (720 URLs, 90 KB) is far under the limits, and no split is needed.
