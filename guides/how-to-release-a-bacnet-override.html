How do I release a BACnet override and give control back to automatic?

Updated 11 October 2026

Short answer

You release an override by writing NULL to the priority slot that holds it, not by writing the “normal” value back. A command sits in one of the point's 16 priority slots until that slot is cleared. In Easy BACnet, turn on write mode, open the point and tap Release to Auto. The app writes NULL at the priority shown in the confirmation (8 unless you chose another), and control drops to the next occupied slot, usually the program's own command, or to Relinquish_Default if every slot is empty.

Why writing a value back doesn't release it

A commandable point has a 16-slot priority array, and the lowest-numbered slot holding a value wins. Say VAV-2-14 ZN-SP has the program writing 72 at priority 16 and you write 68 at priority 8. If you later write 72 at 8, the point still reads 72, but it's still your manual command holding it. When the schedule changes the setpoint at 16, nothing happens, because 8 beats 16. Writing NULL at 8 clears your slot and lets 16 take over again.

Release a point, step by step

  1. Turn on write mode from the menu on the main screen (or the Enable Write Mode button on the point). The release button only appears with write mode on.
  2. Open the point. Commanded At shows the priority in control and the value there; Falls Back To shows the Relinquish_Default.
  3. Check whose command it is. If you wrote it, it's probably at 8. If Commanded At shows a lower number than the slot you used, someone else's command is on top and releasing yours won't change the value.
  4. Tap Release to Auto. The confirmation names the priority it will clear and what the point should fall back to. Tap Release it and the app writes NULL to that slot.
  5. Check the result. The app re-reads the point. Commanded At should now show the next occupied priority, or Not commanded if the array is empty.

Release uses priority 8 unless you picked a different priority on that point screen. If you commanded at, say, 10, tap Write Value, choose 10, tap Review…, cancel the confirmation, then tap Release to Auto; the confirmation will now say priority 10. The Session write log in the main menu lists what you wrote and at which priority.

Only release slots you're responsible for. Clearing a slot another operator or the head-end put there takes away their command too. If a point is held at a higher slot (life safety at 1–2, critical equipment at 5, minimum on/off at 6), releasing your 8 won't change the value, and that's correct.

“I released it but nothing changed”

  • Another slot is still holding it. Look at Commanded At. You can only clear the slot you wrote to.
  • The point isn't commandable. If there's no Commanded At row and no Release to Auto button, the object has no priority array. Your write replaced Present_Value directly; there is nothing to release. Write the original value back, or wait for the program to overwrite it.
  • Something at the controller is driving it. A hand switch, or a point flagged OVERRIDDEN or Out Of Service, takes precedence over network commands. That's a controls or mechanical visit.
  • The values happen to match. If the program's value equals what you had commanded, the number won't move, but control has still gone back to the program.

Before you leave site

Release everything you commanded. A forgotten priority-8 write is the usual reason the next tech finds a point stuck in override weeks later. Write mode turns itself off each time the app starts, but that doesn't touch commands already sitting in a controller. Only a release clears those.
