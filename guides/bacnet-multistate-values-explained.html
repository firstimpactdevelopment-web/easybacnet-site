What do BACnet binary and multi-state values mean?

Updated 11 October 2026

Short answer

Binary and multi-state points hold a state, not a measurement. A binary point is Inactive or Active (0 or 1), which usually means Off or On. A multi-state point holds a number from 1 to N that picks an entry from its State_Text list; for a fan that might be 1 = Off, 2 = Low, 3 = High. The number on its own tells you nothing until you know that list. Neither kind has engineering units.

Binary points

A binary object's Present_Value is Inactive (0) or Active (1). Inputs report a contact, such as a fan status current switch or a filter DP switch; outputs and values can be commanded. The device can also hold Inactive_Text and Active_Text (“Off/On”, “Unoccupied/Occupied”, “Normal/Alarm”). Easy BACnet shows binary values as Active (On) or Inactive (Off), so go by the point name for what Active means on that point. Watch for Polarity on binary I/O: a reversed point reads Active when the contact is open.

Multi-state points

A multi-state object holds an integer from 1 to Number_Of_States. It starts at 1, not 0, and 0 is not a valid value. The names live in the optional State_Text array, where the first entry is state 1. Common examples are occupancy modes (1 Occupied, 2 Unoccupied, 3 Standby), HVAC modes, and fan speeds.

On the point screen Easy BACnet shows the raw state number, and you write a multi-state point by entering the number. Check the State_Text in the head-end or the contractor's points list so you know that 3 means High on this point. A Multi-state control on a custom remote reads State_Text for you, as described below.

Read the number as a list position. A multi-state value of 2 is “the second state,” and the same 2 can mean Low on one point and Unoccupied on another.

Commanding them

Commandable binary and multi-state points use the same priority array as analog points: you write a state at a priority, it holds, and you release it to hand control back. BOs and MSOs are always commandable; BVs and MSVs only if the vendor made them so. Writing a multi-state value above Number_Of_States is rejected by the device. See writing responsibly.

On a custom remote

In the custom remote builder, a binary point fits a Toggle (on and off) or an Indicator status light, and a multi-state point fits the Multi-state control (pick a named state). When you add a Multi-state control, the app reads the point's State_Text, or Number_Of_States if there's no text, and fills in the state names. You can edit them under State names, one per line, first line = state 1.
