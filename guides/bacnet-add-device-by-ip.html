A device won't show up in a scan — can I add it by IP address?

Updated 11 October 2026

Short answer

Yes. If you know the controller's IP address, Easy BACnet can contact it directly instead of relying on a broadcast. A normal scan broadcasts Who-Is, and broadcasts stop at the IP router unless a BBMD forwards them. Use Add device by IP… and the app sends its requests straight to that address, so a controller on another subnet, or on a network that drops broadcasts, can still be read as long as the phone has a route to it.

When to add a device by IP

  • The controller is on a different subnet. For example, you're on 10.20.1.x at the JACE panel, but the chiller plant controllers are on 10.20.5.x, and there's no BBMD.
  • The network drops broadcasts (some managed switches, client isolation on Wi-Fi) but passes unicast.
  • You only need one known controller and don't want to scan a large site.
  • A scan finds everything except one controller whose IP you have.

What you need

  • The controller's IP address. From the as-builts or points list, the head-end's device list, a label in the panel, or the controller's own display.
  • A route to it. If it's on another subnet, the phone needs a gateway that routes there, and the controller needs a correct default gateway of its own or it can't reply. UDP 47808 has to be allowed both ways.
  • Its UDP port, if not 47808. Sites running more than one BACnet IP network sometimes use 47809 or another port in the 47808–47823 (0xBAC0–0xBACF) range.

How to do it in Easy BACnet

  1. In Easy BACnet Mode, open the menu (three dots, top right) and tap Add device by IP…. In Browser Mode it's a button under Scan the network. It's unavailable while a scan is running.
  2. Enter the IP address or host name (e.g. 10.20.5.21) and the UDP port. Leave 47808 unless the site uses another port.
  3. Tap Add. While it shows Contacting…, the app sends a directed Who-Is plus a direct ReadProperty to that address. The read matters because many devices answer a Who-Is with a broadcast I-Am on their own subnet, which won't reach you; a ReadProperty always gets a reply sent back to you.
  4. If the address is a BACnet router, it can answer for the MS/TP controllers behind it, so you may see Added 12 device(s). They join your results like scanned devices: browse points, write, export, or build a custom remote.

If nothing replies you'll get No BACnet IP device answered at…. Work through the checks below.

Seeing a whole remote subnet: BBMD

If the site has a BBMD, open the menu and tap BBMD for remote networks…, enter the BBMD IP address (and port), and tap Save. Each scan then registers the phone with the BBMD as a foreign device and sends the Who-Is through it, so devices on the subnets it serves are found too. Clear goes back to the local subnet only. If the BBMD refuses the registration, foreign-device registration probably isn't enabled on it, and the scan result tells you so.

Adding one device by IP doesn't make the rest of that subnet visible. For the whole network you need a BBMD, which is a conversation with the controls contractor.

If it still doesn't answer

  1. Check the address and port. A typo, or a device on 47809 when you asked on 47808, gets silence.
  2. Make sure the IP is current. As-builts go stale, and a controller left on DHCP can move.
  3. Ping it. No reply means a network problem, not BACnet (though some controllers ignore ping). See is my BACnet device online?
  4. Ask about firewalls and ACLs. If it pings but won't answer BACnet, something in between is probably blocking UDP 47808. That's for whoever owns the network.
