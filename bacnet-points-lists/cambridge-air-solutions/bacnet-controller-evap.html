Cambridge Air Solutions BACnet Controller - EVAP BACnet points list

Updated 4 November 2026

Short answer

The EVAP version of Cambridge's BACnet Controller is a BTL-listed, programmable BACnet MS/TP controller that runs the supply fan, pumps, fill and drain valves and the optional burner of an evaporative cooling unit. Commands, HOA modes, statuses and alarms are mostly multistate values; temperatures, setpoints, delays and water conductivity are analog values, with a few binary values for system enable, water flush and runtime resets. It runs on its own defaults without the network if a zone sensor is connected.

BMS integration notes: Cambridge Air Solutions BACnet Controller - EVAP

Integration in brief

Enable the unit with BV 29501 System Enable and command occupancy with MV 29548 Occupancy Override. Set the zone cooling and heating setpoints (AV 29541/29555), and choose fan and cooling behaviour per occupancy with the Occupied/Unoccupied Fan and Cooling Mode MVs. Read MV 29501 Unit Status, the supply fan status and fault, discharge air temperature and the alarm MVs. Without the network the controller runs on its own defaults as long as a zone sensor is connected.

Enable & remote start

BV 29501 System Enable (0 = disable, 1 = enable). Fan, pump and burner Hand/Off/Auto overrides (MV 29539, 29540, 29562, 29566) and the valve control modes (MV 29541, 29542) should stay in Auto for normal control.

Network setup

  • BACnet MS/TP only, up to 76.8 kbaud. MAC address 4-127 (default 4), set from the local display (Controller > Network) or a MAP gateway; also exposed as AV 29501.
  • Baud defaults to Auto (follows the bus supervisor); the manual suggests 38400 with a Smart Building Hub.
  • Device Object ID (AV 29502) must be unique on the network.
  • Disconnect the controller from the bus while changing network settings, then cycle power before reconnecting.
  • An EOL terminator is needed when the controller is at either end of the MS/TP trunk.

Watch out for

  • Two MV rows in the manual (valve 2 control modes) reuse the valve 1 instances; confirm on site which object the valves actually use.
  • The DAT low temperature alarm needs a manual reset; the other listed alarms reset automatically.
  • Confirm the filter alarm objects on site: MV 25973/25974 (points table) vs MV 29573/29574 (alarm table).
  • Points table defaults and the Default Settings list disagree for some setpoints; read the live values before writing.

Integration notes

  • Optional points (burner, second pump, second fill/drain valves, filter switches, zone sensor, conductivity, fan speed) only apply to units with those options.
  • The input table's Burner Status, Supply Fan Status and Low Water Switch #1/#2 rows point to the same MV objects as the multistate table (MV 29563, 29507, 29535 Sensor 1 Alarms, 29555 Sensor 2 Alarms); they are listed once with the hardware point in the description. The I/O tables show these as 0/1 while the MV table uses 1/2.
  • The manual prints Drain Valve 2 and Fill Valve 2 Control Mode with the same instances as valve 1 (MV 29541/29542), which looks like a typo; only the valve 1 rows are listed.
  • Cooling Type (MV 29557) is printed with placeholder states 1=X, 2=Y, 3=Z; the setup section names the cooling types Direct, Indirect and Direct/Indirect.
  • Default setpoints in the points table (unoccupied cooling 85°F, deadband 0°F) differ from the manual's Default Settings list (75°F, 5°F).
  • Filter A/B are printed as MV 25973/25974, while the alarm table gives the clogged filter switch alarms as MV 29573/29574; 25973/25974 may be a typo. The alarm table also gives the fan alarm as MV 29543 (Effective Occupancy in the points table), where the points table has Supply Fan Fault at MV 29534. Objects are listed here as the points table prints them.

Questions about the Cambridge Air Solutions BACnet Controller - EVAP

How many BACnet points does the Cambridge Air Solutions BACnet Controller - EVAP have?

This list has 101 BACnet objects: 51 analog values, 5 binary values, 45 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Cambridge Air Solutions BACnet Controller - EVAP BACnet points are writable?

57 of the 101 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Cambridge Air Solutions BACnet Controller - EVAP BACnet documentation?

The source is Operating Instructions - BACnet Controller - EVAP (BACnet Controller EVAP Technical Manual) (Version 4.0.2.0003), revision 2023-01-31, published free by Cambridge Air Solutions at https://www.cambridge-eng.com/Portals/0/Operating%20Instructions%204_0_2_0003.pdf.

What are the minimum BACnet points to integrate the Cambridge Air Solutions BACnet Controller - EVAP?

Start with BV 29501 System Enable (Unit enable (1 = enable)); MV 29548 Occupancy Override (Occupied / unoccupied / bypass / standby from the BAS); MV 29546 Occupied Cooling Mode (Occupied cooling: auto / off / on); AV 29541 Occupied Zone Cooling Set Point (Occupied zone cooling setpoint, °F); AV 29555 Occupied Zone Heating Set Point (Occupied zone heating setpoint, °F); MV 29501 Unit Status (Heating / satisfied / cooling / sensor unreliable); MV 29507 Supply Fan Status (Supply fan proven on); AV 29504 Discharge air temperature (Discharge air temperature, °F); MV 29534 Supply Fan Fault (Supply fan alarm); MV 29535 Sensor 1 Alarms (Low water switch 1 alarm (1 = alarm)).

How do I enable BMS control of the Cambridge Air Solutions BACnet Controller - EVAP?

BV 29501 System Enable (0 = disable, 1 = enable). Fan, pump and burner Hand/Off/Auto overrides (MV 29539, 29540, 29562, 29566) and the valve control modes (MV 29541, 29542) should stay in Auto for normal control.

How do I check these points on the real BACnet Controller - EVAP?
