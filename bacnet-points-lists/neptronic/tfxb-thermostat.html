Neptronic TFxB Series Thermostat Controller BACnet points list

Updated 16 October 2026

Short answer

The TFxB24 is a wall thermostat-controller that speaks BACnet MS/TP as a fixed table of AI/AV/BI/BV/MSV objects plus the Device object. Each object is only present on some of the seven model variants (the PDF marks applicability per model), and several multistate objects change their state list depending on how BV.5 (2-pipe/4-pipe) and other settings are configured. It does not issue BACnet event notifications; alarms show only as value changes.

This page lists 73 BACnet objects for the Neptronic TFxB Series Thermostat Controller — 57 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Neptronic’s own free documentation, linked below.

BMS integration notes: Neptronic TFxB Series Thermostat Controller

Integration in brief

Map the space temperature, setpoint and demands, then command occupancy through MSV.13 and the user mode through MSV.3. There is no BMS temperature-feed object; to substitute a value the integrator can only use Out_of_Service, which times out. Setpoints and configuration live in writable AVs.

The short list most integrators start with — enough to run the unit from a BMS. Map more as the job needs.

Enable & remote start

Occupancy is forced from the BMS with MSV.13 OccupancyMode (Occ.Locally lets the thermostat decide; the other two states force occupied or unoccupied). Mode is set with MSV.3; BV.3 decides whether Off is offered.

Sensors & values from the BMS

No dedicated network-temperature object is listed. Values can be overridden by setting Out_of_Service on an input object and writing Present_Value, but the controller returns the object to normal after the Out-of-Service timeout (default 15 minutes).

Network setup

  • BACnet MS/TP, full master; MAC defaults to 1 (000-254, 128-254 are non-token slaves), set from the thermostat menu (password 637).
  • Device instance auto-configures to 153000 + MAC address; can be changed from the menu or by writing Object_Identifier.
  • Baud rate auto-detects (auto detection needs firmware 1.17+), or write Device proprietary property 1001 (9600-76800).
  • Max_Master defaults to 127; set it to the highest MAC on the trunk.

Watch out for

  • Object names in the source carry footnote numbers (e.g. ControlMode13); the real names are shown here without them.
  • Out_of_Service on read-only objects is writable for testing, but it reverts automatically after 15 minutes (Device proprietary property 1002, 0-120 min, 0 = never).
  • AV.1-AV.4, AV.28, AV.36, AV.41, AV.42, BV.7 and MSV.14 are read-only; all other AV/BV/MSV present values are writable.
  • MSV.4 ControlMode restricts what MSV.3 UserControlMode can be set to.

Integration notes

  • Object availability differs by model (TFCB/TFHB, F3 vs P3-OE); the source marks each object per model.
  • Multistate state lists depend on configuration (e.g. BV.5 2-pipe/4-pipe, BV.4 fan auto enable); read State_Text from the device.
  • The Object_List cannot be read in one request; the controller requires reading it one element at a time.
  • Temperatures follow BV.1 Temper.Unit (Celsius or Fahrenheit).

Questions about the Neptronic TFxB Series Thermostat Controller

How many BACnet points does the Neptronic TFxB Series Thermostat Controller have?

This list has 73 BACnet objects: 5 analog inputs, 44 analog values, 1 binary input, 10 binary values, 13 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Neptronic TFxB Series Thermostat Controller BACnet points are writable?

57 of the 73 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Neptronic TFxB Series Thermostat Controller BACnet documentation?

The source is TFxB Series Thermostat Controller BACnet Communication Module User Guide (TFxB24-Bacnet-121026-EUA), revision 2012-10-26, published free by Neptronic at https://www.neptronic.com/controls/PDF/TFxB24-CMUG.pdf.

What are the minimum BACnet points to integrate the Neptronic TFxB Series Thermostat Controller?

Start with AV 1 ControlTemper. (Temperature the thermostat is controlling to); AV 7 Temper.SetPointOcc. (Occupied setpoint (writable)); MV 13 OccupancyMode (BMS occupancy command: local, occupied or unoccupied); MV 14 OccupancyStatus (Actual occupancy state including override); MV 3 UserControlMode (Auto/heat/cool/off mode); AV 2 HeatingDemand (Heating output demand %); AV 3 CoolingDemand (Cooling output demand %); AV 4 FanDemand (Fan demand %).

How do I enable BMS control of the Neptronic TFxB Series Thermostat Controller?

Occupancy is forced from the BMS with MSV.13 OccupancyMode (Occ.Locally lets the thermostat decide; the other two states force occupied or unoccupied). Mode is set with MSV.3; BV.3 decides whether Off is offered.

Can the BMS supply sensor values to the Neptronic TFxB Series Thermostat Controller?

No dedicated network-temperature object is listed. Values can be overridden by setting Out_of_Service on an input object and writing Present_Value, but the controller returns the object to normal after the Out-of-Service timeout (default 15 minutes).
