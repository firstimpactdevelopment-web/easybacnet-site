Neptronic EVCB14N Series VAV Controller BACnet points list

Updated 16 October 2026

Short answer

The EVCB14N is an application-specific VAV box controller with built-in actuator and airflow transducer that communicates over BACnet MS/TP. It exposes a fixed table of AI/AO/AV/BI/BO/BV/MSV objects covering zone temperature, setpoints, heating/cooling ramps, airflow balancing and output configuration. Which objects apply depends on the sub-model (triac count, pressure dependent or independent, feedback).

This page lists 176 BACnet objects for the Neptronic EVCB14N Series VAV Controller — 141 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Neptronic’s own free documentation, linked below.

BMS integration notes: Neptronic EVCB14N Series VAV Controller

Integration in brief

Read the zone temperature, setpoint, demands and airflow, and drive occupancy with MSV.11. To control from a BMS space temperature, set MSV.4 to Network Sensor and keep writing AV.1 ControlTemp faster than the NetworkTimeOut period (AV.145).

Enable & remote start

Occupancy and off are commanded with MSV.11 NsbOccCommand: Locally (wired input/sensor decides), Occupancy, No Occupancy (night setback) or OFF. Changeover can also be forced by the BMS through MSV.3 Cfg_ChangeOverControlMode.

Heartbeat & communication loss

AV.145 NetworkTimeOut (0-60 min): when the temperature source is Network/Remote and the BMS has not written a temperature within this time, the EVC goes to OFF and AV.1 shows 999°C in fault. Setting it to 0 makes AV.1 fall back to the AV.15 setpoint value instead.

Sensors & values from the BMS

Set MSV.4 Cfg_TempControlSource to Network Sensor; AV.1 ControlTemp then becomes writable and must be refreshed by the BMS (see AV.145).

Network setup

  • BACnet MS/TP only; the device instance defaults to 153000 + MAC address (auto) and can be changed from the menu or by writing the Device Object_Identifier.
  • MAC address defaults to 0; baud rate auto-detects (9600/19200/38400/76800), or set it by writing Device proprietary property 1001.
  • Max_Master defaults to 127; lower it to the highest MAC on the trunk for faster token passing.
  • A Copy Config function in the menu can clone one controller's configuration to others of the same type on the trunk.

Watch out for

  • Out_of_Service on read-only objects is writable for testing, but it reverts automatically after 15 minutes (Device proprietary property 1002, 0-120 min, 0 = never).
  • Many multistate objects only offer some states depending on other configuration objects; read State_Text from the device.
  • Cfg_ objects are commissioning parameters; avoid writing them cyclically from the BMS.
  • Airflow objects show "No units"; the value follows the airflow scale set on the controller (MSV.41 Cfg_AirFlowScale where present).

Questions about the Neptronic EVCB14N Series VAV Controller

How many BACnet points does the Neptronic EVCB14N Series VAV Controller have?

This list has 176 BACnet objects: 7 analog inputs, 2 analog outputs, 92 analog values, 3 binary inputs, 4 binary outputs, 39 binary values, 29 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Neptronic EVCB14N Series VAV Controller BACnet points are writable?

141 of the 176 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Neptronic EVCB14N Series VAV Controller BACnet documentation?

The source is EVCB14N Series BACnet Communication Module User Guide (EVCB14N-V508-BACnet Guide-EUA-210818), revision 2021-08-18, published free by Neptronic at http://www.neptronic.com/controls/pdf/20210908/EVCB14N-V508-BACnet%20Guide-EUA-210818.pdf.

What are the minimum BACnet points to integrate the Neptronic EVCB14N Series VAV Controller?

Start with MV 11 NsbOccCommand (BMS occupancy / night setback / off command); AV 15 TempSetPoint (Occupied/day zone setpoint); MV 4 Cfg_TempControlSource (Select internal, external or network temperature); AV 1 ControlTemp (Control temperature; written by the BMS when the source is Network Sensor); MV 12 OccupancyStatus (Actual occupancy state); AV 110 ActualAirFlow (Measured airflow); AV 111 AirFlowSetPoint (Airflow setpoint calculated from demand); AV 93 MotorPosition (Damper actuator position); AV 20 HeatingDemand1 (Heating demand %); AV 40 CoolingDemand1 (Cooling demand %); BV 53 AL_AirFlowError (Airflow problem alarm (0 = No, 1 = Yes)).

How do I enable BMS control of the Neptronic EVCB14N Series VAV Controller?

Occupancy and off are commanded with MSV.11 NsbOccCommand: Locally (wired input/sensor decides), Occupancy, No Occupancy (night setback) or OFF. Changeover can also be forced by the BMS through MSV.3 Cfg_ChangeOverControlMode.

Does the Neptronic EVCB14N Series VAV Controller need a BACnet heartbeat or have a communication timeout?

AV.145 NetworkTimeOut (0-60 min): when the temperature source is Network/Remote and the BMS has not written a temperature within this time, the EVC goes to OFF and AV.1 shows 999°C in fault. Setting it to 0 makes AV.1 fall back to the AV.15 setpoint value instead.

Can the BMS supply sensor values to the Neptronic EVCB14N Series VAV Controller?

Set MSV.4 Cfg_TempControlSource to Network Sensor; AV.1 ControlTemp then becomes writable and must be refreshed by the BMS (see AV.145).

How do I check these points on the real EVCB14N Series VAV Controller?

Scan the network with a BACnet IP browser such as Easy BACnet, open the device and compare its object list with this table. Anything missing is usually an option that isn't installed or a point that is disabled in the controller's configuration.
