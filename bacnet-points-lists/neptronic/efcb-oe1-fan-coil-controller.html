Short answer

The EFCB-OE1 is a variant of Neptronic's EFCB fan coil controller with its own object table on BACnet MS/TP. It adds a fan mode, a selector switch status and alarm objects on top of the usual temperature, setpoint, fan speed, occupancy and output configuration points. Objects apply per model according to the relay count.

This page lists 200 BACnet objects for the Neptronic EFCB-OE1 Series Fan Coil Controller — 168 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Neptronic’s own free documentation, linked below.

BMS integration notes: Neptronic EFCB-OE1 Series Fan Coil Controller

Integration in brief

Map the control temperature, setpoint, system mode and fan speed, and drive occupancy with MSV.13 NsbOccCommand. To use a BMS space temperature, set MSV.21 Cfg_TempControlSource to Network and keep AV.1 ControlTemp refreshed within the AV.2 Cfg_NetworkTimeOut period.

Enable & remote start

Occupancy and off are commanded with MSV.13 NsbOccCommand (Locally, Off, Occupancy/Day, No Occupancy/Night). Mode is written to MSV.1 SystemMode; whether Off is allowed depends on BV.3. Changeover can be forced by the BMS via MSV.10.

Heartbeat & communication loss

AV.2 Cfg_NetworkTimeOut (0-60 min): if MSV.21 is Network/Remote and no temperature has been written within this time, the EFC goes to Off and AV.1 shows 999°C in fault. Setting 0 makes AV.1 fall back to the AV.9 setpoint value.

Sensors & values from the BMS

Set MSV.21 Cfg_TempControlSource to Network (Net); AV.1 ControlTemp then becomes writable and must be refreshed by the BMS within AV.2.

Network setup

  • BACnet MS/TP only; the device instance defaults to 153000 + MAC address (auto) and can be changed from the menu or by writing the Device Object_Identifier.
  • MAC address defaults to 0; baud rate auto-detects (9600/19200/38400/76800), or set it by writing Device proprietary property 1001.
  • Max_Master defaults to 127; lower it to the highest MAC on the trunk for faster token passing.
  • A Copy Config function in the menu can clone one controller's configuration to others of the same type on the trunk.

Watch out for

  • Out_of_Service on read-only objects is writable for testing, but it reverts automatically after 15 minutes (Device proprietary property 1002, 0-120 min, 0 = never).
  • Output ramps (analog, triac and relay) are assigned by Cfg_ multistate objects; their options depend on 2-pipe/4-pipe and other settings.
  • Cfg_ objects are commissioning parameters; do not write them cyclically.
  • Object availability differs between the 2-relay and 4-relay models.
  • BV.42 reports the local/remote selector switch; with the switch in Local the unit is under local control.

Questions about the Neptronic EFCB-OE1 Series Fan Coil Controller

How many BACnet points does the Neptronic EFCB-OE1 Series Fan Coil Controller have?

This list has 200 BACnet objects: 8 analog inputs, 4 analog outputs, 90 analog values, 4 binary inputs, 11 binary outputs, 48 binary values, 35 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Neptronic EFCB-OE1 Series Fan Coil Controller BACnet points are writable?

168 of the 200 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Neptronic EFCB-OE1 Series Fan Coil Controller BACnet documentation?

The source is Fan Coil Controller EFCB-OE1 Series BACnet Communication Module User Guide (EFCB-OE1-BACnet Guide-EUA-160318), revision 2016-03-18, published free by Neptronic at https://www.neptronic.com/controls/PDF/EFC/BACnetModbus/EFCB-OE1-BACnet%20Guide-EUA-160318.pdf.

What are the minimum BACnet points to integrate the Neptronic EFCB-OE1 Series Fan Coil Controller?

Start with MV 13 NsbOccCommand (BMS occupancy / night setback / off command); MV 1 SystemMode (Auto/fan/heat/cool/off mode); AV 9 TempSetPoint (Occupied/day zone setpoint); MV 2 UserFanSpeedSelect (Fan speed (auto/low/medium/high)); MV 21 Cfg_TempControlSource (Select network, internal or external temperature); AV 1 ControlTemp (Control temp; BMS writes it when the source is Network); MV 14 OccupancyStatus (Actual occupancy state); AV 20 HeatingDemand (Heating ramp demand, %); AV 35 CoolingDemand (Cooling ramp demand, %).

How do I enable BMS control of the Neptronic EFCB-OE1 Series Fan Coil Controller?

Occupancy and off are commanded with MSV.13 NsbOccCommand (Locally, Off, Occupancy/Day, No Occupancy/Night). Mode is written to MSV.1 SystemMode; whether Off is allowed depends on BV.3. Changeover can be forced by the BMS via MSV.10.

Does the Neptronic EFCB-OE1 Series Fan Coil Controller need a BACnet heartbeat or have a communication timeout?

AV.2 Cfg_NetworkTimeOut (0-60 min): if MSV.21 is Network/Remote and no temperature has been written within this time, the EFC goes to Off and AV.1 shows 999°C in fault. Setting 0 makes AV.1 fall back to the AV.9 setpoint value.

Can the BMS supply sensor values to the Neptronic EFCB-OE1 Series Fan Coil Controller?

Set MSV.21 Cfg_TempControlSource to Network (Net); AV.1 ControlTemp then becomes writable and must be refreshed by the BMS within AV.2.

How do I check these points on the real EFCB-OE1 Series Fan Coil Controller?
