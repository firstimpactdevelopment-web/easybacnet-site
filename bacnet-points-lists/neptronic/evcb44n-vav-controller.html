Updated 16 October 2026

Short answer

The EVCB44N is a newer-generation Neptronic VAV controller that communicates over BACnet MS/TP with a fixed object table, plus schedule, program and file objects. Points include zone temperature, humidity, CO2 and VOC readings from the room sensor, setpoints, demands and airflow. Pressure-dependent models do not use the airflow objects.

BMS integration notes: Neptronic EVCB44N Series VAV Controller

Integration in brief

Read the zone temperature, setpoint, demands and airflow, and drive occupancy with MSV.11. To control from a BMS space temperature, set MSV.4 to Network Sensor and keep writing AV.1 ControlTemp faster than the NetworkTimeOut period (AV.145).

Enable & remote start

Occupancy and off are commanded with MSV.11 NsbOccCommand: Locally (wired input/sensor decides), Occupancy, No Occupancy (night setback) or OFF. Changeover can also be forced by the BMS through MSV.3 Cfg_ChangeOverControlMode.

Heartbeat & communication loss

AV.145 NetworkTimeOut (0-60 min): when the temperature source is Network/Remote and the BMS has not written a temperature within this time, the EVC goes to OFF and AV.1 shows 999°C in fault. Setting it to 0 makes AV.1 fall back to the AV.15 setpoint value instead.

Sensors & values from the BMS

Set MSV.4 Cfg_TempControlSource to Network Sensor; AV.1 ControlTemp then becomes writable and must be refreshed by the BMS (see AV.145).

Network setup

  • BACnet MS/TP only; the device instance defaults to 153000 + MAC address (auto) and can be changed from the menu or by writing the Device Object_Identifier.
  • MAC address defaults to 0; baud rate auto-detects (9600/19200/38400/76800), or set it by writing Device proprietary property 1001.
  • Max_Master defaults to 127; lower it to the highest MAC on the trunk for faster token passing.
  • A Copy Config function in the menu can clone one controller's configuration to others of the same type on the trunk.

Watch out for

  • Out_of_Service on read-only objects is writable for testing, but it reverts automatically after 15 minutes (Device proprietary property 1002, 0-120 min, 0 = never).
  • Many multistate objects only offer some states depending on other configuration objects; read State_Text from the device.
  • Cfg_ objects are commissioning parameters; avoid writing them cyclically from the BMS.
  • Airflow objects show "No units"; the value follows the airflow scale set on the controller (MSV.41 Cfg_AirFlowScale where present).

Questions about the Neptronic EVCB44N Series VAV Controller

How many BACnet points does the Neptronic EVCB44N Series VAV Controller have?

This list has 122 BACnet objects: 5 analog inputs, 1 analog output, 71 analog values, 1 binary input, 28 binary values, 16 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Neptronic EVCB44N Series VAV Controller BACnet points are writable?

94 of the 122 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Neptronic EVCB44N Series VAV Controller BACnet documentation?

The source is EVCB44N Series BACnet Communication Module User Guide (EVCB44NxS-V5.10-BACnet Guide-251121), revision 2025-11-21, published free by Neptronic at http://www.neptronic.com/Controls/pdf/2026/EVCB44NxS-V5.10-BACnet%20Guide-251121.pdf.

What are the minimum BACnet points to integrate the Neptronic EVCB44N Series VAV Controller?

Start with MV 11 NsbOccCommand (BMS occupancy / night setback / off command); AV 15 TempSetPoint (Occupied/day zone setpoint); MV 4 Cfg_TempControlSource (Select internal, external or network temperature); AV 1 ControlTemp (Control temp; BMS writes it when MSV.4 = Network Sensor); MV 12 OccupancyStatus (Actual occupancy state); AV 110 ActualAirFlow (Measured airflow); AV 111 AirFlowSetPoint (Airflow setpoint calculated from demand); AV 20 HeatingDemand1 (Heating ramp demand, %); AV 40 CoolingDemand1 (Cooling ramp demand, %); BV 53 AL_AirFlowError (Airflow problem alarm (0 = No, 1 = Yes)).

How do I enable BMS control of the Neptronic EVCB44N Series VAV Controller?

Occupancy and off are commanded with MSV.11 NsbOccCommand: Locally (wired input/sensor decides), Occupancy, No Occupancy (night setback) or OFF. Changeover can also be forced by the BMS through MSV.3 Cfg_ChangeOverControlMode.

Does the Neptronic EVCB44N Series VAV Controller need a BACnet heartbeat or have a communication timeout?

AV.145 NetworkTimeOut (0-60 min): when the temperature source is Network/Remote and the BMS has not written a temperature within this time, the EVC goes to OFF and AV.1 shows 999°C in fault. Setting it to 0 makes AV.1 fall back to the AV.15 setpoint value instead.

Can the BMS supply sensor values to the Neptronic EVCB44N Series VAV Controller?

Set MSV.4 Cfg_TempControlSource to Network Sensor; AV.1 ControlTemp then becomes writable and must be refreshed by the BMS (see AV.145).

How do I check these points on the real EVCB44N Series VAV Controller?

Scan the network with a BACnet IP browser such as Easy BACnet, open the device and compare its object list with this table. Anything missing is usually an option that isn't installed or a point that is disabled in the controller's configuration.
