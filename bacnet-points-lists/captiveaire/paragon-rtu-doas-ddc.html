Short answer

CaptiveAire's Paragon rooftop units and DOAS are run by the unit's own controller board; BACnet comes from a factory-mounted Protocessor gateway in the control panel, set up at the factory for either BACnet IP (Ethernet) or BACnet MS/TP (RS-485). The 300 objects cover DDC commands, occupied/unoccupied setpoints, the on-board schedule, mode selections, sensor readings, compressor/ERV data and six active fault codes. The simplest BMS control is to enable scheduling once, set the on-board schedule to unoccupied (1440) and drive BV-5 DDCOccupiedOverride.

BMS integration notes: CaptiveAire Paragon RTU / DOAS DDC (Protocessor BACnet)

Integration in brief

Turn on scheduling once (BV-216), set every on-board schedule slot (AV-46..87) to 1440 so the unit is always unoccupied by its own clock, then command occupancy from the BMS with BV-5. Let the unit run on its own setpoints (intake/space/discharge, chosen by the Activate Based On and Tempering Mode AVs) and monitor UnitStatus, temperatures and the six fault-code AIs. Only use the raw DDC heat/cool/blower commands if the tempering modes are set to DDC.

Enable & remote start

BMS occupancy control needs BV-216 SchedulingEnabledFlag on and all internal schedule AVs (46-87) at 1440; an occupied input always wins over unoccupied, so any non-1440 slot keeps the unit occupied regardless of BV-5. Direct heat/cool/blower commands (BV-1..3, AV-4) need the heat/cool tempering modes (AV-217..220) set to DDC (3).

Sensors & values from the BMS

A BMS space temperature can be written to AV-248 ExternalSpaceTempValue after enabling BV-247 ExternalSpaceTempEnable; space humidity likewise via BV-269 ExternalSpaceRhEnable and AV-270 ExternalSpaceRhValue. BV-280..283 act as virtual thermostat calls when Activate Based On is set to Stat (4).

Network setup

  • Protocessor default device instance 50001, MS/TP MAC 51, 38400 baud, Max Master 127; the guide increments instance and MAC per unit number.
  • Protocessor default IP 192.168.1.24 /255.255.255.0; web configurator login admin/admin (or the password printed by the Ethernet port).
  • The gateway is factory set to either BACnet IP or MS/TP for the job; objects are only reachable on that port.
  • Each changed gateway parameter needs its own Submit and a system restart.

Watch out for

  • If any internal schedule slot is not 1440, BV-5 cannot turn the unit off during that slot.
  • The controller board reboots when some factory settings are changed.
  • Gas valve output reads 10 V both at high fire and when the unit is not heating.
  • Setpoints used depend on Activate Based On (AV-221/222) and Tempering Mode (AV-217..220); unused setpoints have no effect.
  • Blower speed AVs (88-91) must stay within the min/max speed limits in AV-228..235.

Integration notes

  • Protocessor defaults: device instance 50001, MS/TP MAC 51, 38400 baud, Max Master 127, IP 192.168.1.24; increment instance/MAC per unit.
  • For BMS occupancy control set BV-216 SchedulingEnabledFlag on once, set schedule AVs 46-87 to 1440 (no schedule), then write BV-5.
  • DDC heat/cool/blower commands (BV-1..3, AV-4) only act when the tempering mode AVs (217-220) are set to DDC (3).
  • Fault AIs 210-215 return codes from the guide's fault table; temperatures follow the unit's F/C setting. The guide lists no engineering units.
  • Access comes from the guide's Control/Monitor vs Monitor Only column; BI-294..296 are listed as Control/Monitor but are inputs, so shown read-only here.
  • Points depend on unit options (gas/electric heat, DX stages, ERV, economizer); unused ones read zero or are meaningless.

What are the minimum BACnet points to integrate the CaptiveAire Paragon RTU / DOAS DDC (Protocessor BACnet)?

Start with BV 5 DDCOccupiedOverride (Occupied/unoccupied command from the BMS); BV 216 SchedulingEnabledFlag (Must be on (once) for BV-5 to work); AI 139 UnitStatus (Idle / blower / heating / cooling state); AI 140 CurrentOccupiedStatus (Confirms the occupancy command took effect); AI 148 DischargeTemp (Discharge air temperature); AI 141 AverageSpaceTemp (Space temperature the unit is controlling to); AV 18 SpaceCoolOccSP (Occupied space cooling setpoint); AV 8 SpaceHeatOccSP (Occupied space heating setpoint); AI 210 ActiveFault1 (First active fault code).

How do I enable BMS control of the CaptiveAire Paragon RTU / DOAS DDC (Protocessor BACnet)?

BMS occupancy control needs BV-216 SchedulingEnabledFlag on and all internal schedule AVs (46-87) at 1440; an occupied input always wins over unoccupied, so any non-1440 slot keeps the unit occupied regardless of BV-5. Direct heat/cool/blower commands (BV-1..3, AV-4) need the heat/cool tempering modes (AV-217..220) set to DDC (3).

Can the BMS supply sensor values to the CaptiveAire Paragon RTU / DOAS DDC (Protocessor BACnet)?

A BMS space temperature can be written to AV-248 ExternalSpaceTempValue after enabling BV-247 ExternalSpaceTempEnable; space humidity likewise via BV-269 ExternalSpaceRhEnable and AV-270 ExternalSpaceRhValue. BV-280..283 act as virtual thermostat calls when Activate Based On is set to Stat (4).
