Short answer

The Series 8000 is a multi-circuit electrical submeter that reports each configured meter over BACnet IP. Every meter gets total active, reactive and apparent power and power factor, per-element current, voltage, power, power factor and phase angle, present and peak demand, and energy accumulators. The object count scales with the meter configuration; this list is Leviton's 3P-08 example with 216 analog inputs and 40 accumulators.

BMS integration notes: Leviton VerifEye Series 8000 multi-circuit meter (3P-08 example)

Integration in brief

A read-only meter: poll or trend the per-meter power, demand and energy objects for the circuits you need. Use the accumulators for energy totals and the present demand objects for load. Configure the meter layout first, because the object count and numbering follow it.

Network setup

  • BACnet IP on UDP port 47808 by default; BBMD address and timeout (default 60000) are set in the configuration tool.
  • Device ID, description, location and object name are set in the Meter Shop / factory configuration tool; the default device ID shown is 4194303.
  • The example unit lists vendor ID 425 (Triacta Power Technologies).

Watch out for

  • Every meter ships with device ID 4194303; give each one a unique device ID before adding several to a network.
  • Writing property 1501 on the device object clears peak demand on every meter at once.
  • Object numbering changes with the meter configuration; re-discover objects after changing it.

Integration notes

  • Taken from '2.1 Points List Summary' (pp6-11), printed as an image of a BACnet browser tree; read by OCR and checked against the page. It is the 3P-08 example: other configurations (3P-02, 1P/2P-03, 1P/2P-06, 1P/2P-12, 1P/2P-24) change how many meters and elements exist, so the instance numbers shift.
  • Instances run in blocks of eight meters: AI 0-31 per-meter totals, AI 32-199 per-element values (current, voltage, active/reactive/apparent power, power factor, phase angle; elements 0-2), AI 200-215 peak and present demand, ACC 0-39 energy registers.
  • Accumulators are BACnet Accumulator objects (type 23). The doc's sample property dump shows watt_hours as the units property on every accumulator, including the reactive and apparent registers; units for the analog inputs are not given.
  • Access is inferred: the doc has no read/write column; all objects are inputs or accumulators and are listed read-only.
  • Peak demand timestamp: proprietary property 1500 on each peak demand object (Unix 32-bit time). Writing any value to property 1501 on the device object resets peak demand on all meters.
