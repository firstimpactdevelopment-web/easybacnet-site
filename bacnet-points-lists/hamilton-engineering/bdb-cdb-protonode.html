Short answer

Hamilton Engineering's BDB-CDB control is read over Modbus RTU by a ProtoNode FPC-N54 and served on BACnet IP or BACnet MS/TP. The 99-object profile has writable central heating, DHW, indirect DHW, pool and spa setpoints, cascade sensor readings and an anomaly code, then a 9-object block for each of BCB1 to BCB8. This file lists the cascade objects and the BCB1 block.

BMS integration notes: Hamilton Engineering BDB-CDB (ProtoNode FPC-N54)

Integration in brief

Wire the BDB-CDB Modbus port (9600, 8N1) to the ProtoNode R1 port, pick BACnet IP or BACnet MS/TP in the Web Configurator, add the BDB-CDB profile with Node-ID 32, and discover the device at 50032. Setpoints are the writable analog values; status and fault information comes from the cascade anomaly and the per-board working status and anomaly codes.

Network setup

  • Device instance = Node_Offset (default 50,000) + Node-ID; the BDB-CDB profile uses Node-ID 32, so 50032 by default.
  • Modbus side (R1 port): Modbus RTU 9600, 8N1. BMS RS-485 on the R2 port; bias resistors are DIP switches on each port.
  • Default IP 192.168.1.24 (255.255.255.0); the field protocol is chosen with the Protocol Selector in the Web Configurator.
  • Each ProtoNode on a subnet needs its own BACnet Network Number (default 50001).

Watch out for

  • Boiler blocks repeat every 9 instances (BCB n = BCB1 + 9 x (n - 1)); only BCB1 is listed here.
  • The guide gives no units, ranges or code tables; confirm values with Hamilton Engineering.

Integration notes

  • Per-boiler blocks repeat every 9 objects: BCB n = the BCB1 instance + 9 x (n - 1), so BCB2 is AI/MI 37-45 and BCB8 is AI/MI 91-99.
  • The guide only names the device BDB-CDB and does not expand BCB; it does not say which Hamilton products use it.
  • The table has no read/write column, units or state texts; access is inferred from object type (AV writable, AI/MI read only).
  • The two anomaly code 2 parts are multistate inputs; their state texts are not given.

Questions about the Hamilton Engineering BDB-CDB (ProtoNode FPC-N54)

How many BACnet points does the Hamilton Engineering BDB-CDB (ProtoNode FPC-N54) have?

This list has 36 BACnet objects: 16 analog inputs, 18 analog values, 2 multi-state inputs. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Hamilton Engineering BDB-CDB (ProtoNode FPC-N54) BACnet points are writable?

18 of the 36 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done. The source has no read/write column, so this is inferred from object type.

Where is the official Hamilton Engineering BDB-CDB (ProtoNode FPC-N54) BACnet documentation?

The source is ProtoNode FPC-N54 Start-up Guide for Interfacing Hamilton Engineering Products: BDB-CDB (Document Revision 2.A (Web Configurator Template Revision 3)), revision 2019-06, published free by Hamilton Engineering at https://hamiltonengineering.com/wp-content/uploads/ProtoNode-FPC-N54-Start-up-Guide-06.19.pdf.

What are the minimum BACnet points to integrate the Hamilton Engineering BDB-CDB (ProtoNode FPC-N54)?

Start with AV 2 CH Requests (Central heating request; values not defined in the guide); AV 11 Boiler For Heating Setpoint (Boiler setpoint for the heating load); AV 12 Dhw SP Temp (Domestic hot water setpoint); AI 31 BCB1 Working Status (BCB1 working status); AI 21 Cascade S1 Temp Sensor Value (Cascade sensor S1 temperature); AI 27 Cascade Anomaly (Cascade-level anomaly (fault) code); AI 32 BCB1 Anom Code 1 (BCB1 anomaly code).

How do I check these points on the real BDB-CDB (ProtoNode FPC-N54)?

Scan the network with a BACnet IP browser such as Easy BACnet, open the device and compare its object list with this table. Anything missing is usually an option that isn't installed or a point that is disabled in the controller's configuration.
