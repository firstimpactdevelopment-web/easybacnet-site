Short answer

The Smart Controller Protocol Converter puts a Heatcraft Smart Controller (Beacon II refrigeration) on BACnet. It exposes per-system status (box temperature, mode, alarms, compressor cycles and runtime, defrost times, setpoints) and per-evaporator status (defrost, error code, EXV position, suction temperature and pressure, superheat), plus writable setpoint objects in the 1000s and mode-parameter bits in the 14000s.

BMS integration notes: Heatcraft Smart Controller Protocol Converter (BACnet) for Beacon II / Smart Controller refrigeration

Integration in brief

Read each system's box temperature, operating mode and alarm bits, and the per-evaporator error codes. Setpoints are changed through the '_sp' objects (for example the box temperature, alarm limits and defrost times); the status objects only read back. Several mode and alarm objects share printed instances, so confirm them with a device scan.

The short list most integrators start with — enough to run the unit from a BMS. Map more as the job needs.

Watch out for

  • Because of the type/instance clashes in the bulletin, verify object types with a device scan before mapping.
  • Defrost start time values are coded, not clock times; use the bulletin's conversion table.
  • System 1 mode (s_1_md) and the alarm bits (s_1_alm_bit_0-3) are printed on AV 2-6, which the bulletin also gives to other objects (pswd, s_1_al_dur_tm, s_2_md); confirm their real instances on the device before mapping them.

Integration notes

  • Object names here are the bulletin's reference names (e.g. s_1_box_t); the display names are in the descriptions.
  • The bulletin's object type column is inconsistent: Sys 1 and Sys 2 alarm, op-mode and mode-parameter bits are printed as AV while the Sys 3 and Sys 4 ones are BV, and some Sys 3 Unit 3 analog statuses are printed as BV. As a result about 20 type + instance pairs appear twice (for example AV 1 = smrt_cntrlr_ver, com_er and bacnet_wr_pri). Everything is listed as printed; confirm with a device discovery.
  • Status objects are read-only; the matching '_sp' setpoint objects (AV 1381-1634, BV 143xx) are the writable ones.
  • Error code status values combine Beacon II / QRC codes E1-E7 (sensor faults, low superheat, compressor shut-down); defrost start times use a time code. Both tables are in the bulletin.
