Lennox Prodigy M3 BACnet Module BACnet points list

Updated 16 October 2026

Short answer

The M3 BACnet module plugs onto a Lennox Prodigy M3 rooftop unit controller and exposes it as a BACnet MS/TP device (BTL listed, B-ASC). The BAS drives the unit by writing Analog Outputs (mode, occupancy, setpoints, enables) and reads status from Analog Inputs; occupied/unoccupied setpoints live in Analog Values. The device instance defaults to the MS/TP MAC address. The module expects regular writes from the BAS; if they stop, it times out and falls back to its local control mode.

This page lists 83 BACnet objects for the Lennox Prodigy M3 BACnet Module — 33 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Lennox’s own free documentation, linked below.

BMS integration notes: Lennox Prodigy M3 BACnet Module

Integration in brief

Enable the BACnet module in the M3 setup wizard and set the MAC address, baud and Control Mode. In Room Sensor mode the BMS writes occupancy (AO104) and setpoints (AO109 or AV130-133), and can supply space temperature on AO113. In Network Thermostat mode it sends heat/cool/fan demands on AO101 instead. The M3 does not store commands, so every control point in use must be rewritten on a schedule and after every controller reset.

Enable & remote start

At the M3: SETUP > INSTALL wizard, set Configuration ID 1 position 5 to B to enable the BACnet module. Then SETUP > NETWORK INTEGRATION > BACNET to set the address, baud and CONTROL MODE (Monitor Only, Room Sensor, Network Thermostat, Zone or Remote). In Monitor Only the unit ignores network setpoints and mode demands. No occupancy jumper is needed for Zone/Remote modes.

Heartbeat & communication loss

Network space temperature (AO113) and space RH/CO2 must be rewritten at least every 5 minutes (2-minute interval recommended), or an alarm is raised; some of these alarms only clear with a local reset. AO101 (network thermostat demand), AO109, AV130-133 and AO104 (when not using setpoint control) must be rewritten within 15 minutes (7-minute interval recommended). Without network sensor data for 5 minutes the unit shows Alarm 73. In Room Sensor mode with BACnet setpoints, 15 minutes with no application-level BACnet traffic makes the RTU reset. In Network Thermostat mode, 15 minutes without demands switches it to its backup mode. After losing network data the unit defaults to occupied (Parameter 225 changes this).

Sensors & values from the BMS

Space temperature goes to AO113 (Space Temperature Input) when CONTROL MODE = ROOM SENSOR with network TEMPERATURE = YES. Space RH and CO2 are written to the proprietary space air object properties 536 and 537. Before network sensor data arrives the unit idles up to 5 minutes (Alarm 110), then enters backup sensor mode (Alarm 93). The points list has no network outdoor-air-temperature input.

Network setup

  • Default device instance (Object_Identifier) equals the MS/TP MAC address; change it from the BACnet front end.
  • Default object name is Lennox_M3_ followed by the MAC address.
  • Baud is selectable 9.6k, 19.2k, 38.4k or 76.8k; default 38.4k. Max_Master defaults to 127 and Max_Info_Frames to 1.
  • Use consecutive MAC addresses starting at 1, and set Max_Master to the highest MAC on the trunk.
  • Lennox recommends no repeaters and, above 9.6k baud, no more than 20 Lennox units and 30 devices per router.

Watch out for

  • Lennox does not support BACnet COV; poll instead, no faster than every 2 minutes per point.
  • Commands are not stored: rewrite all control points after every M3 reset.
  • Use ReadPropertyMultiple when reading many analog objects.
  • AV134-AV140 airflow targets only work with SmartAirflow.
  • AI200-AI207 (IMC Version) are legacy and not recommended for new jobs.

Integration notes

  • Default baud 38.4k; Max_Master 127; Max_Info_Frames 1.
  • Network values should be refreshed at least every 12 minutes (software v7.08+); the communication time-out is 15 minutes (5 minutes before v7.08).
  • AO101 Application Mode Control takes coded values (heat/cool/fan/exhaust and direct stage commands); see the source for the full code table.
  • AI200-AI207 (IMC Version characters) are legacy and not recommended for new installations.
  • AV134-AV140 airflow targets only apply when SmartAirflow is installed; ranges depend on cabinet size.
  • The module also has Lennox proprietary object types (compressor, blower, heating, economizer, air sensors) with no instance list; they are not included here.

Questions about the Lennox Prodigy M3 BACnet Module

How many BACnet points does the Lennox Prodigy M3 BACnet Module have?

This list has 83 BACnet objects: 50 analog inputs, 20 analog outputs, 13 analog values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Lennox Prodigy M3 BACnet Module BACnet points are writable?

33 of the 83 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Lennox Prodigy M3 BACnet Module BACnet documentation?

The source is M3 BACnet Module (Unit Information) (Corp 1404-L4 (450402)), revision 2018-10, published free by Lennox at https://www.lennox.com/dA/0082a46061/1404e.pdf.
