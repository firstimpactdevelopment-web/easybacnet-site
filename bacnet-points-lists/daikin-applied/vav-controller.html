Daikin Applied Daikin VAV Controller (BACnet MS/TP) BACnet points list

Updated 28 October 2026

Short answer

The Daikin VAV controller is a combined damper actuator and DDC controller for pressure-independent VAV boxes, BTL listed as a B-ASC on BACnet MS/TP. It runs one of nine application programs (6630-6637 plus 6684 slave mode), and some object instances change name and meaning with the application. Most objects are AO/BO values stored in EEPROM, so the BAS should write them sparingly.

This page lists 104 BACnet objects for the Daikin Applied Daikin VAV Controller (BACnet MS/TP) — 96 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Daikin Applied’s own free documentation, linked below.

BMS integration notes: Daikin Applied Daikin VAV Controller (BACnet MS/TP)

Integration in brief

Address the controller and pick the application with the WCIS software (network settings cannot be set from the BAS). The BAS then switches DAY.NGT for occupancy, adjusts the day setpoints and reads room temperature, airflow and damper position. Keep writes to the AO/BO objects to a minimum because they go to EEPROM.

Enable & remote start

No separate enable. DAY.NGT (BO 29) selects day or night setpoints and is normally written by the field panel. The controller only controls once an application (6630-6637) is selected; out of the box it runs 6684 slave mode with no control. CTL TEMP (AO 78) and the active flow limits (AO 76, AO 77) follow their normal sources unless overridden.

Sensors & values from the BMS

Room temperature, CO2 and RH come from the wired room unit (AI 4, AI 125, AI 126). CTL TEMP (AO 78) is ROOM TEMP plus RMTMP OFFSET unless it is overridden; the guide gives no timeout for an override.

Network setup

  • Use WCIS to set CTLR ADDRESS (MAC, use 1-127), device instance, baud, Max Masters and application; these cannot be set from the BAS.
  • Defaults: MAC 255, device instance 3101014, baud 38400, Max Masters 127, initial value priority 15.
  • First power-up runs application 6684 (slave mode, no control) until an application number is written.
  • Run the checkout (CHK OUT, BO 66) after commissioning and read the bit-added result in CHK STATUS (AO 70).

Watch out for

  • AO/BO writes go to EEPROM/Flash with a finite write count; do not write setpoints cyclically.
  • Object names and meaning of some instances change with the application number.
  • Many values are calculated or configuration objects even though they are AO/BO R/W (e.g. DMPR POS, FLOW, CHK STATUS).
  • CAL MODULE states are printed as 0=YES, 1=NO, the reverse of the other YES/NO points.

Integration notes

  • Some instances carry a different object name per application (e.g. BO 46 is DO 6 or FAN); those are shown as 'name A / name B'.
  • The source prints the AO 2 name as 'APPLICATIONOFF'; elsewhere it is called APPLICATION.
  • AO 26 and AO 27 are both printed as SERIES OFF (AO 26 is the series fan on threshold).
  • Gain objects are printed as CLG l GAIN, HTG l GAIN and FLOW l GAIN (lowercase L) and kept as printed.
  • Points marked as 'unbundled' in the guide are the ones meant to be exposed individually to a BAS; the rest stay bundled in the application.
  • Writable AO/BO objects are stored in EEPROM/Flash with a limited write life.

Questions about the Daikin Applied Daikin VAV Controller (BACnet MS/TP)

How many BACnet points does the Daikin Applied Daikin VAV Controller (BACnet MS/TP) have?

This list has 104 BACnet objects: 7 analog inputs, 79 analog outputs, 3 binary inputs, 15 binary outputs. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Daikin Applied Daikin VAV Controller (BACnet MS/TP) BACnet points are writable?

96 of the 104 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Daikin Applied Daikin VAV Controller (BACnet MS/TP) BACnet documentation?

The source is Daikin VAV Controller BACnet MS/TP Network Integration (Table 4: BACnet Point List) (ED 19157), revision April 2026, published free by Daikin Applied at https://tahoeweb.daikinapplied.com/api/general/DownloadDocumentByName/media/ED%2019157%20Daikin%20VAV%20Controller%20BACnet%20Protocol%20Document.pdf/.

What are the minimum BACnet points to integrate the Daikin Applied Daikin VAV Controller (BACnet MS/TP)?

Start with BO 29 DAY.NGT (Occupancy command: 0 = day, 1 = night); AO 6 DAY CLG STPT (Day (occupied) cooling setpoint); AO 7 DAY HTG STPT (Day (occupied) heating setpoint); BO 5 HEAT.COOL (Current mode: 0 = cool, 1 = heat); AI 4 ROOM TEMP (Room temperature from the sensor); AO 92 CTL STPT (Setpoint the temperature loop is using); AI 35 AIR VOLUME (Measured airflow, CFM); AO 49 DMPR POS / MTR1 POS (Damper position, % (calculated from run time)); AO 99 ERROR STATUS (Power-up error code; 0 = no errors).

How do I enable BMS control of the Daikin Applied Daikin VAV Controller (BACnet MS/TP)?

No separate enable. DAY.NGT (BO 29) selects day or night setpoints and is normally written by the field panel. The controller only controls once an application (6630-6637) is selected; out of the box it runs 6684 slave mode with no control. CTL TEMP (AO 78) and the active flow limits (AO 76, AO 77) follow their normal sources unless overridden.

Can the BMS supply sensor values to the Daikin Applied Daikin VAV Controller (BACnet MS/TP)?

Room temperature, CO2 and RH come from the wired room unit (AI 4, AI 125, AI 126). CTL TEMP (AO 78) is ROOM TEMP plus RMTMP OFFSET unless it is overridden; the guide gives no timeout for an override.
