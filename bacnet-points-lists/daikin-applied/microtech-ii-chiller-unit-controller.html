Daikin Applied MicroTech II Chiller Unit Controller BACnet points list

Updated 4 November 2026

Short answer

The MicroTech II chiller unit controller connects to BACnet MS/TP or BACnet IP/Ethernet through a BACnet communication module (a LonWorks module also exists). The object list is the same for both: enable, mode, cool/heat/ice setpoints and capacity limit commands, water temperatures and flows, chiller status and mode, refrigerant and oil data per compressor, compressor current/power/voltage, run hours and starts, pump status and alarm objects. Which objects return data depends on the chiller model; a model-support matrix in the doc shows which.

This page lists 128 BACnet objects for the Daikin Applied MicroTech II Chiller Unit Controller — 9 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Daikin Applied’s own free documentation, linked below.

BMS integration notes: Daikin Applied MicroTech II Chiller Unit Controller

Integration in brief

Set the chiller's control source to the network (BAS) at the keypad or touch screen, then write ChillerEnable, the operating mode, the cool setpoint and the capacity limit. Read UnitStatus, ActiveMode, water temperatures, capacity and AlarmDigitalOutput, and use ClearAlarm for clearable alarms.

Enable & remote start

Disable the chiller, set the protocol to the BAS network at the user interface, then set the setpoint source to Network (on centrifugals, Control Source = BAS on the SETPOINTS/MODE screen, password 2001; other models use the passwords in the doc's table). Re-enable the chiller; ChillerEnable (BV 41) then starts and stops it.

Heartbeat & communication loss

The receive-heartbeat and default-value behaviour described in the doc applies to the LonWorks interface only. No BACnet heartbeat point is listed.

Network setup

  • MS/TP defaults: device instance 3000, MAC 18, 38400 baud, Max Master 127, Max Info Frames 20; set with Daikin's BACnet Configuration Tool and cycle power afterwards.
  • IP module defaults: 172.16.5.8, mask 255.255.0.0, UDP 47808, device instance 3000; settings are changed in the module's web configuration interface (IM 837).
  • Device name is MTII Chiller UC plus the device instance; changing the instance changes every object's full reference.
  • Use CompSelect (MO 46) and PumpSelect (MO 47) to choose which compressor or pump the 'selected' objects report.

Watch out for

  • ClearAlarm (BV 42) can't clear shutdown faults on centrifugals such as low evaporator pressure, high condenser pressure, low oil pressure, freeze protection and high motor temperature; on other models only the flow-loss alarm can be cleared remotely.
  • Run-hour objects report hours divided by 10.
  • The heat setpoint is ignored while the chiller is in cool mode.
  • Many objects only return data on certain chiller types; check the model-support table before mapping.

Integration notes

  • ED 15062-9 (BACnet MS/TP + LonWorks) and ED 15100-5 (BACnet IP/Ethernet) print the same 128 objects with the same instances and object names; the IP doc adds a Variable Index column for the web configuration interface.
  • Points that ask for 'the selected compressor' or 'the selected pump' return data for whatever CompSelect (MO 46) or PumpSelect (MO 47) is set to; other compressors and pumps also have their own fixed objects.
  • Run-hour values (compressor and pump hours) must be multiplied by 10 to get actual hours.
  • AI 82 (oil sump pressure, compressor 2) is printed with the object name Comp2OilFeedPress, the same as AI 81; kept as printed.
  • Ranges list both English and SI units; English units are shown here.
  • Object availability depends on chiller model (centrifugal, scroll, screw, Turbocor/WMC).

Questions about the Daikin Applied MicroTech II Chiller Unit Controller

How many BACnet points does the Daikin Applied MicroTech II Chiller Unit Controller have?

This list has 128 BACnet objects: 105 analog inputs, 4 analog outputs, 8 binary inputs, 2 binary values, 6 multi-state inputs, 3 multi-state outputs. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Daikin Applied MicroTech II Chiller Unit Controller BACnet points are writable?

9 of the 128 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Daikin Applied MicroTech II Chiller Unit Controller BACnet documentation?

The source is MicroTech II Chiller Unit Controller Protocol Information (LonWorks, BACnet MS/TP) (ED 15062-9), revision 2022-08, published free by Daikin Applied at https://tahoeweb.daikinapplied.com/api/general/DownloadDocumentByName/media/Daikin_ED_15062-9_MTII_Chiller_Unit_Controller_Protocol_Info_Tech_Sheet.pdf/.

What are the minimum BACnet points to integrate the Daikin Applied MicroTech II Chiller Unit Controller?

Start with BV 41 ChillerEnable (Enable (1) / disable (0) the chiller); MO 45 ChillerOperationMode (Mode command: 1=Ice, 2=Cool, 3=Heat); AO 29 NetworkCoolTempSetpoint (Leaving chilled water setpoint); AO 32 NetworkCapacityLimitPct (Capacity limit from the BMS, %); MI 43 UnitStatus (Off/Start/Run/Pre-shutdown/Service); BI 38 ChillerLocalRemote (Reads Remote (0) when network control is allowed); AI 2 LvgEvapWaterTempUnit (Leaving chilled water temperature); AI 1 EntEvapWaterTemp (Entering chilled water temperature); AI 9 ChillerCapacity (Running capacity, %); BI 40 AlarmDigitalOutput (Any active alarm).

How do I enable BMS control of the Daikin Applied MicroTech II Chiller Unit Controller?

Disable the chiller, set the protocol to the BAS network at the user interface, then set the setpoint source to Network (on centrifugals, Control Source = BAS on the SETPOINTS/MODE screen, password 2001; other models use the passwords in the doc's table). Re-enable the chiller; ChillerEnable (BV 41) then starts and stops it.

Does the Daikin Applied MicroTech II Chiller Unit Controller need a BACnet heartbeat or have a communication timeout?

The receive-heartbeat and default-value behaviour described in the doc applies to the LonWorks interface only. No BACnet heartbeat point is listed.

How do I check these points on the real MicroTech II Chiller Unit Controller?

Scan the network with a BACnet IP browser such as Easy BACnet, open the device and compare its object list with this table. Anything missing is usually an option that isn't installed or a point that is disabled in the controller's configuration.
