Short answer

PreciseLine light air handlers use a MicroTech 4 Lite unit controller with a built-in BACnet MS/TP port (T14). The list covers sensor inputs, network sensor overrides, occupancy and application mode commands, temperature, humidity and duct static setpoints, PI tuning, runtimes, alarm objects and, on VRV-coil units, D-Kit or EV-kit status and error codes. Many points only apply when the matching sensor, option or VRV kit is configured.

BMS integration notes: Daikin Applied MicroTech PreciseLine Light Air Handler Controller

Integration in brief

Set the MS/TP address, baud and device instance from the remote HMI, then occupy the unit with Network Occupancy Schedule (MV 9) and pick the mode with Application Mode (MV 5). Adjust the occupied heating/cooling setpoints and read Unit State, space temperature and the alarm objects. Network sensor values (space temp, OAT, humidity, CO2) are optional overrides of the local sensors.

Enable & remote start

No BAS-enable switch is described. Network Occupancy Schedule (MV 9) is the recommended occupancy input and applies while the local Occupancy Command (MV 8) is at its default Auto; Network Occupancy Command (MV 7) overrides the keypad. Application Mode (MV 5) takes the last valid write from either the network or the HMI. MV 36-39 can enable or disable economizer, cooling, heating and dehumidification (Null = local setting).

Heartbeat & communication loss

No heartbeat or receive timer. All network values stay at the last valid value if communication is lost. MV 7, MV 9 and MV 36-39 return to their defaults when the controller resets.

Sensors & values from the BMS

Network Space Temperature (AV 8), Network Entering Water Temperature (AV 9), Network Outdoor Air Temperature (AV 10), Network Space CO2 (AV 22), Network Space Humidity (AV 24) and Network Outdoor Humidity (AV 25) override the local sensors; if the network value is invalid or not written, the controller falls back to the local sensor. Effective values read back on AV 1-7 and AV 23. Network Supply Fan Speed (AV 118) sets the fan speed from the BAS.

Network setup

  • Defaults: device instance 23, MAC address 18, 38400 baud, Max Master 127, Max Info Frames 10, device name PL AHU_23.
  • Set addressing on the remote HMI (Unit Maintenance > BACnet MSTP Set-Up, Manager level), then set Apply Changes to Yes; the controller resets.
  • Connect the MS/TP trunk to port T14; the remote HMI uses port TH.
  • Max APDU 480, no segmentation.

Watch out for

  • Do not write Clear Alarms (MV 3) continuously; write it only to clear a known alarm.
  • Some alarms use intelligent reset: they self-clear the first two times in 7 days, then lock out until cleared manually.
  • Active alarms can stop BAS-commanded values from taking effect.
  • Points for sensors or options that are not installed read 32767.

Integration notes

  • BACnet MS/TP only; there is no BACnet IP port on this controller.
  • Fifth edition of ED 19126 (first released June 2023). Revision -2 added the VRV D-Kit points, -3 energy recovery, and -4 (August 2026) the R-32 EV-kit and A2L leak-detection points.
  • VRV points (CSV 1-8, MV 42-45, MV 48-72, AV 128-131, AV 144-183, BI 31-38) only apply to units with Daikin VRV outdoor units; D-Kit = R-410A, EV kit = R-32.
  • Unconfigured or failed sensors read 32767.
  • Temperature units follow MV 1 (English or SI); the list shows English units except where the guide gives only °C.

What are the minimum BACnet points to integrate the Daikin Applied MicroTech PreciseLine Light Air Handler Controller?

Start with MV 9 NetOccSchedStat (Occupancy command from the BMS schedule); MV 5 AppModeSel (Application mode (Auto/Heat/Cool/Fan Only/Off)); AV 11 OccClgSp (Occupied cooling setpoint); AV 12 OccHtgSp (Occupied heating setpoint); MV 3 ClearAlms (Clear alarms (all or by class)); MV 4 UnitState (Unit operating state); AV 3 EffSpaceTemp (Space temperature used for control); AI 1 aiDAT (Discharge air temperature); AV 127 ActiveAlarm (Highest-priority active alarm number).

How do I enable BMS control of the Daikin Applied MicroTech PreciseLine Light Air Handler Controller?

No BAS-enable switch is described. Network Occupancy Schedule (MV 9) is the recommended occupancy input and applies while the local Occupancy Command (MV 8) is at its default Auto; Network Occupancy Command (MV 7) overrides the keypad. Application Mode (MV 5) takes the last valid write from either the network or the HMI. MV 36-39 can enable or disable economizer, cooling, heating and dehumidification (Null = local setting).

Does the Daikin Applied MicroTech PreciseLine Light Air Handler Controller need a BACnet heartbeat or have a communication timeout?

No heartbeat or receive timer. All network values stay at the last valid value if communication is lost. MV 7, MV 9 and MV 36-39 return to their defaults when the controller resets.

Can the BMS supply sensor values to the Daikin Applied MicroTech PreciseLine Light Air Handler Controller?

Network Space Temperature (AV 8), Network Entering Water Temperature (AV 9), Network Outdoor Air Temperature (AV 10), Network Space CO2 (AV 22), Network Space Humidity (AV 24) and Network Outdoor Humidity (AV 25) override the local sensors; if the network value is invalid or not written, the controller falls back to the local sensor. Effective values read back on AV 1-7 and AV 23. Network Supply Fan Speed (AV 118) sets the fan speed from the BAS.
