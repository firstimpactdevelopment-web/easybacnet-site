Short answer

The MicroTech chiller unit controller exposes a shared BACnet object list across several Daikin Applied chiller families when fitted with the BACnet MS/TP or BACnet IP communication module. The table covers analog inputs, analog values, binary inputs, binary values and multi-state values, with network setpoints (cool, ice, capacity limit, enable, mode) commandable at any priority. BMS integration notes: Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator)

Integration in brief

Set Chiller Local/Network to Network at the unit keypad, then enable the chiller with ChillerEnableStp and write the cool setpoint, mode and capacity limit as needed. Read unit status, leaving water temperature, capacity and the alarm code objects for monitoring.

Enable & remote start

Chiller Local/Network must be set to Network at the unit keypad (it cannot be changed over the network). The BMS then writes ChillerEnableStp (BV 2) = Enable; this only permits the chiller to run when other conditions are satisfied, it does not force a start.

Heartbeat & communication loss

The guide's communication parameter table lists Receive Heartbeat as N/A for BACnet IP and MS/TP; the heartbeat (nciRcvHrtBt) only applies to LonWorks.

Network setup

  • Initial device instance is calculated from the production code (IP) or MAC address (MS/TP); change it at the keypad and cycle power.
  • BACnet IP defaults: DHCP on, UDP port 47808.
  • BACnet MS/TP defaults: MAC address 18, 38400 baud, Max Master 127.

Watch out for

  • Network setpoint and enable objects are commandable; any priority can be written over BACnet MS/TP or IP.
  • Some compressor-shutdown alarms (e.g. low evaporator / high condenser pressure) cannot be cleared from the network.
  • Many per-compressor and VFD points exist only on certain models or with the optional VFD package.
  • Several pressure and current objects duplicate one sensor to support intrinsic alarming; map just one.

Integration notes

  • Point availability depends on chiller model; the guide includes a per-model availability matrix.
  • Initial device instance is calculated from the production code (IP) or MAC address (MS/TP) and can be changed at the keypad.
  • Several compressor current and refrigerant pressure objects read the same physical sensor; extra copies exist for intrinsic alarming.
  • Voltage, power, current and percent RLA per compressor need the optional VFD package on AWS units.
  • Object names such as C1Comp11Kilowatts are kept exactly as printed.
  • Network setpoints only take effect when the chiller's control source is set to network/BAS at the HMI.
  • BACnet alarm objects from Table 12 (alarm BIs/BVs and notification classes) are included. BV 668, 670, 676, 678, 704, 706, 711 and 713 are printed twice with circuit and compressor names (e.g. C1Comp1OFFCondPressHi); the first name is kept. NC 2 and NC 3 are printed with an NC1- prefix.
  • Intrinsic alarm objects listed only in Tables 19-21 (by notification class) are also included; the doc gives no access or states for them, so they are marked R with empty states.

Questions about the Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator)

How many BACnet points does the Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator) have?

This list has 433 BACnet objects: 101 analog inputs, 49 analog values, 87 binary inputs, 187 binary values, 3 notification classs, 6 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator) BACnet points are writable?

128 of the 433 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator) BACnet documentation?

The source is MicroTech Chiller Unit Controller Protocol Information (ED 15120-11), revision 2023-10, published free by Daikin Applied at https://tahoeweb.daikinapplied.com/api/general/DownloadDocumentByName/media/MicroTech%20Unit%20Controller%20LonWorks-BACnet%20Tech%20Sheet%20-%20ED%2015120-11.pdf/.

What are the minimum BACnet points to integrate the Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator)?

Start with BV 2 ChillerEnableStp (Network enable/disable of the chiller); AV 4 NetworkCoolTempSetpoint (Leaving water cool setpoint from the BMS); MV 3 ChillerOperationMode (Cool/Ice/Heat mode command); AV 3 NetworkCapacityLimitPct (Demand/capacity limit from the BMS); BI 3 ChillerLocalRemote (Confirms the chiller is accepting network commands); MV 1 UnitStatus (Off/Start/Run/Preshutdown/Service status); AI 2 LvgEvapWaterTempUnit (Leaving chilled water temperature); AV 2 ChillerCapacity (Actual capacity in percent); AV 905 AVFaultAlarmCode (Active fault alarm code); BV 8 ClearAlarm (Clear alarms from the network).

How do I enable BMS control of the Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator)?

Chiller Local/Network must be set to Network at the unit keypad (it cannot be changed over the network). The BMS then writes ChillerEnableStp (BV 2) = Enable; this only permits the chiller to run when other conditions are satisfied, it does not force a start.

Does the Daikin Applied MicroTech Chiller Unit Controller (Pathfinder, Trailblazer, Magnitude WME-B, Navigator) need a BACnet heartbeat or have a communication timeout?

The guide's communication parameter table lists Receive Heartbeat as N/A for BACnet IP and MS/TP; the heartbeat (nciRcvHrtBt) only applies to LonWorks.
