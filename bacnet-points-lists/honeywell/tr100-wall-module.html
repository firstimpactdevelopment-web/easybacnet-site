Honeywell TR100 wall module (BACnet MS/TP) BACnet points list

Updated 21 November 2026

Short answer

The TR100 is a touchscreen room wall module that measures space temperature (plus humidity on TH models and CO2 on THC models) and gives the room user setpoint, fan, HVAC mode and occupancy override buttons. On BACnet MS/TP it exposes its readings as Analog Inputs, and its configuration and the values a controller writes for display as Analog, Binary and Multistate Values. Most objects are meant to be exchanged with a master controller; many are bit masks.

This page lists 72 BACnet objects for the Honeywell TR100 wall module (BACnet MS/TP) — 63 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Honeywell’s own free documentation, linked below.

BMS integration notes: Honeywell TR100 wall module (BACnet MS/TP)

Integration in brief

Enable BACnet MS/TP on the TR100 touchscreen, give it a unique device ID and let it auto-detect the baud rate and MAC. Read the space readings and the room user's selections (setpoint, fan, HVAC mode, occupancy override); write the occupancy mode and, if wanted, a setpoint and the values to display.

Enable & remote start

BACnet MS/TP is off until enabled on the touchscreen (swipe left, Connection, BACnet MS/TP).

Sensors & values from the BMS

The controller can write values for the module to display (AQI, CO2, humidity, PM, TVOC, UV index, fresh air, AV 2-15) and the displayed temperature (AV 51); 32767 means not available. A setpoint written to AV 605 is stored, limited by AV 602/603 and shown as AV 604; the controller then writes 0x7FFF again to mean no change.

Network setup

  • Default device instance 4194302; enter a unique Device ID on the touchscreen.
  • Auto baud for the first 4 minutes after start-up or enable; falls back to 38400 if no rate is found (e.g. single device). Baud can be set manually.
  • Auto-MAC addressing is on by default (MAC range defaults 1-30); a manual MAC can be entered.
  • Max Master default 127, Max Info Frames default 10.

Watch out for

  • Many objects are bit masks (alarms, display selection, allowed overrides, reset); write the summed bit value.
  • Persistent settings (Cfg_ objects) are stored in flash; AV 605 writes go to flash only when the value differs, so write 0x7FFF between changes as the guide describes.
  • AV 203 Cfg_OverrideReset clears room-user overrides by bit (setpoint, fan, HVAC mode, occupancy).

Integration notes

  • Object names are printed wrapped and hyphenated across lines in a narrow column; they are rejoined here without the wrap hyphens and spaces (e.g. Cfg_FanOverride). Spellings such as ni_PM2.5Oudoor, Cfg_AlloweOverridesFromOCC and no_TeperatureSetpointLimited are as printed.
  • AV 103 is printed with the name no_CleaningModeStatus, but its range and description are the room user's minimum fan stage/level (the partner of AV 104 Cfg_FanUserMaxSpeed). MV 11 CleaningModeStatus is the actual cleaning mode status.
  • AV 505 (Cfg_AllowedOverridesFromSTANDBY) and MV 505 (Cfg_BrandType) share instance 505 but are different object types.
  • Display values written by the controller (AV 2-15, AV 51, AV 102) use 32767 (0x7FFF) to mean not available.
  • Humidity objects apply to TR100-TH-G and TR100-THC-G; CO2 objects to TR100-THC-G only.
  • Device object properties (Object_Identifier, MS/TP MAC range, baud rate, brand text and Honeywell firmware-update properties) are also listed in the guide; they are device properties, not separate objects, and are left out here.

Questions about the Honeywell TR100 wall module (BACnet MS/TP)

How many BACnet points does the Honeywell TR100 wall module (BACnet MS/TP) have?

This list has 72 BACnet objects: 3 analog inputs, 56 analog values, 2 binary values, 11 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Honeywell TR100 wall module (BACnet MS/TP) BACnet points are writable?

63 of the 72 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Honeywell TR100 wall module (BACnet MS/TP) BACnet documentation?

The source is TR100 Wall Module BACnet Integration Guide (31-00676M-02), revision Rev. 09-25, published free by Honeywell at https://prod-edam.honeywell.com/content/dam/honeywell-edam/hbt/en-us/documents/manuals-and-guides/installation-guides/tr-100/hon-ba-bms-tr100-bacnet-integration-guide-31-00676m-02-drop-3-d1-3.pdf.

What are the minimum BACnet points to integrate the Honeywell TR100 wall module (BACnet MS/TP)?

Start with MV 32 ni_OccMdFromSchedAndOccSensor (Occupancy mode from the controller schedule); AV 605 Cfg_SetptUser (Setpoint write from controller; 0x7FFF = no change); AI 1 no_SpaceTempReading (Space temperature); AI 2 no_SpaceHumiReading (Space humidity (TH and THC models)); AI 3 no_SpaceCO2Reading (Space CO2, ppm (THC model)); AV 604 no_TeperatureSetpointLimited (Effective setpoint after min/max limits); MV 21 Cfg_UserSelectedHVACMode (HVAC mode picked by the room user); AV 101 Cfg_FanOverride (Room user fan override; 0x7FFF = auto); AV 501 Cfg_UserSelectedOccupancyMode (Room user occupancy override); AV 701 no_AlarmInfoFromWallModule (Wall module alarm bits (sensor, comm, limits)).

How do I enable BMS control of the Honeywell TR100 wall module (BACnet MS/TP)?

Can the BMS supply sensor values to the Honeywell TR100 wall module (BACnet MS/TP)?

The controller can write values for the module to display (AQI, CO2, humidity, PM, TVOC, UV index, fresh air, AV 2-15) and the displayed temperature (AV 51); 32767 means not available.
