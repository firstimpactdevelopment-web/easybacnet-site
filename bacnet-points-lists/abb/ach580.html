Short answer

The ACH580 has BACnet MS/TP built into its EFB (RS-485) terminal, enabled with parameter 58.01. Its fixed object list covers relay and digital I/O status, run/stop and direction commands, speed references, energy meters, fault and warning history, two PID loops and ten user-mapped Data-IO values. BACnet IP needs a separate adapter (e.g. FBIP-21), which is not covered by this list.

BMS integration notes: ABB ACH580 HVAC drive (embedded BACnet MS/TP)

Integration in brief

Set 58.01 Protocol enable = BACnet MSTP, then 58.03 node address, 58.04 baud and 58.40 Device object ID, save with 96.07 and apply with 58.06 Refresh settings. Point 20.01 Ext1 commands at Embedded fieldbus and the Ext1 frequency or speed reference (28.11 or 22.11) at EFB ref1, then command BV10 and AV16. Configure 58.14-58.16 so the drive reacts to a lost BMS.

Enable & remote start

Set 20.01 Ext1 commands (and 20.07 Ext2) to Embedded fieldbus so BV10 starts and stops the drive; 20.21 Direction = Request lets BV11 set direction. For the reference set 28.11 Ext1 frequency ref1 = EFB ref1 (scalar mode, the default) or 22.11 Ext1 speed ref1 = EFB ref1 (vector) for AV16; ref2/AV17 uses 28.15 or 22.18. 19.11 = EFB MCW bit 11 lets BV13 choose Ext1/Ext2, and 20.40/20.41/20.42 = Embedded fieldbus hand run permissive and start interlocks to BV12, BV20 and BV21. BV18 Control-Override-Command takes control from the normal source, but panel HAND still has priority.

Heartbeat & communication loss

BACnet has no built-in timeout, so the drive uses 58.14 Communication loss action (default No action; also Fault, Last speed, Speed ref safe via 22.41/28.41, Fault always, Warning), 58.15 Communication loss mode (default Cw/Ref1/Ref2, meaning only control word or reference writes reset the timer; or Any message) and 58.16 Communication loss time (0-6000 s, default 30 s). In the default mode the BMS must keep rewriting the command or reference. Loss gives fault 6681 or warning A7CE EFB comm loss; there is a 30 s boot-up delay, and changes need a reboot or 58.06 Refresh settings.

Sensors & values from the BMS

For the process PID set 40.08 Set 1 feedback 1 source = Feedback data storage and 40.16 Set 1 setpoint 1 source = Setpoint data storage, then write AV43 LOOP-Feedback and AV42 LOOP-Setpoint. AO0/AO1 drive the analog outputs when 13.12/13.22 = AO data storage, and BO0-BO5 drive the relays when their source is an RO/DIO control word bit.

Network setup

  • 58.01 Protocol enable = BACnet MSTP turns on the EFB port.
  • 58.03 Node address is the MS/TP MAC; the manual lists 254 as the BACnet default, so set it to a valid address yourself.
  • 58.04 sets the baud rate.
  • 58.40 Device object ID sets the device instance (unique, 1-4194303); the device object's default instance is 4194303.
  • After changing group 58, save with 96.07 Parameter save manually and apply with 58.06 Communication control = Refresh settings.
  • 58.07-58.13 are diagnostic counters (58.13 counts tokens received) for checking the MS/TP link.

Watch out for

  • Panel HAND mode beats BACnet control override (BV18).
  • BV39 Parameter-Save-Command writes permanent memory; use it once, not cyclically.
  • Last speed and Speed ref safe keep the motor running after a comm loss; make sure that is safe.
  • Fault reset through BV14 always goes through; no source parameter is needed.
  • AV120-AV129 Data-IO objects only carry data after parameters 58.101-58.110 are mapped.

Integration notes

  • Set the device instance with parameter 58.40 Device object ID; it must be unique on the network.
  • Commands (BV10-BV14, AV16/AV17) only take effect when the drive's start/reference sources are set to embedded fieldbus.
  • AV120-AV129 (Data-IO-1..10) carry whatever drive parameters are mapped in 58.101-58.110.
  • Gaps in the instance numbering are reserved by ABB and do not exist on the drive.
  • MSV1-MSV3 state lists print 'Output-Phase-Loss Motor-Stall' without a comma; split here into two states.
  • The manual lists BO4 with the name RO4-Command although it controls relay 5; kept as printed.

Questions about the ABB ACH580 HVAC drive (embedded BACnet MS/TP)

How many BACnet points does the ABB ACH580 HVAC drive (embedded BACnet MS/TP) have?

This list has 129 BACnet objects: 2 analog inputs, 2 analog outputs, 63 analog values, 12 binary inputs, 6 binary outputs, 35 binary values, 2 loops, 7 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which ABB ACH580 HVAC drive (embedded BACnet MS/TP) BACnet points are writable?

46 of the 129 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

What are the minimum BACnet points to integrate the ABB ACH580 HVAC drive (embedded BACnet MS/TP)?

Start with BV 10 RUN-STOP-Command (Start/stop from the BMS); AV 16 Input-Reference-1 (Speed reference in %); BV 14 Fault-Reset-Command (Reset a tripped drive); BV 0 RUN-STOP-Monitor (Running status); BV 2 OK-FAULT-Monitor (Fault status); BV 4 HAND-AUTO-Monitor (Shows if the panel has the drive in Hand); AV 1 Output-Freq (Output frequency); AV 4 Output-Current (Motor amps); AV 6 Output-Power (Drive power in kW); MV 1 Active-Fault-1 (Which fault is active).

How do I enable BMS control of the ABB ACH580 HVAC drive (embedded BACnet MS/TP)?

Set 20.01 Ext1 commands (and 20.07 Ext2) to Embedded fieldbus so BV10 starts and stops the drive; 20.21 Direction = Request lets BV11 set direction. For the reference set 28.11 Ext1 frequency ref1 = EFB ref1 (scalar mode, the default) or 22.11 Ext1 speed ref1 = EFB ref1 (vector) for AV16; ref2/AV17 uses 28.15 or 22.18. 19.11 = EFB MCW bit 11 lets BV13 choose Ext1/Ext2, and 20.40/20.41/20.42 = Embedded fieldbus hand run permissive and start interlocks to BV12, BV20 and BV21. BV18 Control-Override-Command takes control from the normal source, but panel HAND still has priority.

Does the ABB ACH580 HVAC drive (embedded BACnet MS/TP) need a BACnet heartbeat or have a communication timeout?

BACnet has no built-in timeout, so the drive uses 58.14 Communication loss action (default No action; also Fault, Last speed, Speed ref safe via 22.41/28.41, Fault always, Warning), 58.15 Communication loss mode (default Cw/Ref1/Ref2, meaning only control word or reference writes reset the timer; or Any message) and 58.16 Communication loss time (0-6000 s, default 30 s). In the default mode the BMS must keep rewriting the command or reference. Loss gives fault 6681 or warning A7CE EFB comm loss; there is a 30 s boot-up delay, and changes need a reboot or 58.06 Refresh settings.

For the process PID set 40.08 Set 1 feedback 1 source = Feedback data storage and 40.16 Set 1 setpoint 1 source = Setpoint data storage, then write AV43 LOOP-Feedback and AV42 LOOP-Setpoint. AO0/AO1 drive the analog outputs when 13.12/13.22 = AO data storage, and BO0-BO5 drive the relays when their source is an RO/DIO control word bit.
