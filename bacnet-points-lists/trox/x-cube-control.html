Short answer

TROX X-CUBE air handlers are controlled by a factory PLC (X-CUBE Control) that connects to a BMS over BACnet IP. TROX publishes the maximum data point list as an EDE-style table: 17 BMS write objects (heartbeat, reset, system mode, standby, external outdoor temperature and fan/temperature/humidity setpoints), about 100 analog inputs for temperatures, humidities, pressures, airflows, valve/damper/fan positions and filter data, and over 600 binary inputs for alarms, fire dampers, fans and heat recovery. Which objects are live depends on the unit's actual configuration.

This page lists 743 BACnet objects for the TROX X-CUBE Control BACnet data point list — 17 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from TROX’s own free documentation, linked below.

BMS integration notes: TROX X-CUBE Control BACnet data point list

Integration in brief

Write AO-5 eInSystemMode = 2 (auto) and keep BO-7 bInSPStandby false so the unit runs, toggle BO-1 bInHeartBeat2PLC so the PLC sees the BMS, and set the supply/extract fan and temperature/humidity setpoints in AO-8..17. Read back AI-89 eOutPVOperationMode, AI-1 eOutEventNotification and the main temperatures, and use BO-2 to reset errors. The list marks the objects that must be set in green; those are the AO/BO block.

Enable & remote start

AO-5 eInSystemMode sets the operation mode (0=unit off, 1=manual, 2=auto); the unit runs in auto only when eInSystemMode is 2, BO-7 bInSPStandby is false and there is no critical error.

Heartbeat & communication loss

BO-1 bInHeartBeat2PLC is the heartbeat from the BMS to the unit PLC and BI-0 bOutHeartbeat2BMS is the PLC's heartbeat back to the BMS. The list does not state a timeout or what the unit does if the BMS heartbeat stops.

Sensors & values from the BMS

A BMS outdoor temperature can be written to AO-6 fInMeasTempOutdoor. No source-select or timeout object is listed for it.

Network setup

  • BACnet IP; the EDE example uses device instance 200 (device object name TROX_856581), which is unit specific.

Watch out for

  • Fan and temperature setpoints have default 0 and full float range in the list; write sensible values before enabling auto.
  • BO-4 bInTestFireDampers starts a test of all fire dampers.
  • Many alarm BIs are described as 'normally closed' contacts; check polarity during commissioning.
  • Humidity setpoints (AO-12/13, 16/17) are in g/kg (absolute), while humidity readings are %RH.

Integration notes

  • This is the maximum list; objects for components a unit doesn't have (extra fans, dampers, fire dampers, KVS run-around coil) stay unused.
  • BMS write objects are the AO/BO block (BO-1..4, AO-5..17); everything else is read-only.
  • Units come from the EDE unit-code column (BACnet engineering unit enums: 62=°C, 98=%, 53=Pa, 135=m³/h, 29=%RH, 28=g/kg, 96=ppm, 48=W, 71=h).
  • Binary inputs reference state-text table 1, which is not printed in this document.
  • Fan setpoints AO-8/9 carry no engineering unit in the list.

Questions about the TROX X-CUBE Control BACnet data point list

How many BACnet points does the TROX X-CUBE Control BACnet data point list have?

This list has 743 BACnet objects: 103 analog inputs, 12 analog outputs, 619 binary inputs, 5 binary outputs, 1 device, 2 files, 1 other. The exact set on a given unit depends on its firmware, installed options and configuration.

Which TROX X-CUBE Control BACnet data point list BACnet points are writable?

17 of the 743 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official TROX X-CUBE Control BACnet data point list BACnet documentation?

The source is BACnet EDE-File XCUBE (BACnet DPL) (V003), revision 2014-10, published free by TROX at https://www.trox.de/en/downloads/ad12a8c8fa3e2cc5/bacnet.pdf.

What are the minimum BACnet points to integrate the TROX X-CUBE Control BACnet data point list?

Start with AO 5 eInSystemMode (Operation mode command: 0 off, 1 manual, 2 auto); BO 7 bInSPStandby (Standby when true; must be false for auto run); BO 1 bInHeartBeat2PLC (BMS-to-PLC heartbeat); AI 89 eOutPVOperationMode (Actual operating mode); AI 1 eOutEventNotification (No error / warning / critical error); AI 3 fOutPVTempSUP (Supply air temperature); AI 4 fOutPVTempETA (Extract air temperature); AO 8 fInSPFanSUP (Supply fan setpoint); AO 14 fInSPTempSUPMin (Minimum supply air temperature setpoint); BO 2 bInResetErrors (Resets all errors).

How do I enable BMS control of the TROX X-CUBE Control BACnet data point list?

AO-5 eInSystemMode sets the operation mode (0=unit off, 1=manual, 2=auto); the unit runs in auto only when eInSystemMode is 2, BO-7 bInSPStandby is false and there is no critical error.

Does the TROX X-CUBE Control BACnet data point list need a BACnet heartbeat or have a communication timeout?

BO-1 bInHeartBeat2PLC is the heartbeat from the BMS to the unit PLC and BI-0 bOutHeartbeat2BMS is the PLC's heartbeat back to the BMS. The list does not state a timeout or what the unit does if the BMS heartbeat stops.

Can the BMS supply sensor values to the TROX X-CUBE Control BACnet data point list?

A BMS outdoor temperature can be written to AO-6 fInMeasTempOutdoor. No source-select or timeout object is listed for it.
