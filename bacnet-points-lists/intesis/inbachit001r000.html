Short answer

A one-unit Intesis interface that sits on a Hitachi indoor unit's remote-controller bus and serves it as a BACnet MS/TP or BACnet IP device. It exposes 31 fixed objects (on/off, mode, setpoint, fan, louvre, room temperature, errors, filter, occupancy logic and remote-controller lock). Several indoor units on the same remote-controller bus can be connected but they are all driven as one group.

BMS integration notes: Intesis INBACHIT001R000 (Hitachi VRF gateway)

Integration in brief

Connect the gateway to the indoor unit (two-wire A/B remote-controller bus, gateway port RC2, up to 500 m), set the BACnet network on its DIP switches, then write the _command objects (on/off, mode, setpoint, fan) and read back the matching _status objects. One gateway serves one indoor unit (or one remote-controller group), so give each gateway its own MAC address and device instance.

Enable & remote start

No enable point or BMS/local switch is documented; the gateway accepts BACnet commands as soon as it is communicating with the unit. A wired remote controller can still be used in parallel; BV 2 LockRemoteControl locks it.

Sensors & values from the BMS

Write a BMS room temperature to AO 1 RoomTemperature_command. BI 14 VirtualTempActive shows whether the gateway is using it, and AI 17 UserSetPoint_status shows the user setpoint written from BACnet while it is active (AI 0 then shows the setpoint actually applied).

Network setup

  • BACnet MS/TP or BACnet IP is chosen with a DIP switch (MS/TP is the default); switch changes need a power cycle.
  • BACnet IP: factory static IP 192.168.100.246; change it (or select DHCP) with the Intesis configuration tool.
  • MS/TP MAC address 0-127 is set on DIP switches; baud rate is DIP-selectable (9600-115200) with autobaud as the default.
  • Default device instance 246000. In automatic mode the instance is a base (246000, changeable in the configuration tool) + the SW2 MAC address; it can also be set manually or by writing Object_Identifier.
  • SW4 sets the gateway as slave (default) or master on the Hitachi A/B bus.
  • The gateway is normally powered from the AC unit; a mini-USB port can power it for bench testing.

Watch out for

  • Every function has a separate _command (AO/BO/MO, commandable) and _status (AI/BI/MI) object; write the command, read the status.
  • Temperatures follow the Celsius/Fahrenheit DIP switch; the BACnet Units property changes with it.
  • The Occupancy MV and its four AVs drive built-in logic that sets mode, setpoint and on/off; leave Occupancy at 3 (Disabled) unless you use it, and any manual on/off, mode or setpoint change cancels it.
  • Several indoor units on one A/B bus are commanded together; individual commands to them are not possible.

Integration notes

  • The member-object table lists ErrorReset as BI 5 but its object section is a Binary Output; it is listed here as BO 5.
  • The capacity table says 33 objects; the member table lists 31 plus the Device object.
  • Units shown as °C follow the °C/°F DIP switch.
  • ErrorCodeM state texts are the Hitachi error codes listed in the manual's error-code chapter.
  • UserSetPoint_status and VirtualTempActive report the virtual-temperature function driven by RoomTemperature_command.

Questions about the Intesis INBACHIT001R000 (Hitachi VRF gateway)

How many BACnet points does the Intesis INBACHIT001R000 (Hitachi VRF gateway) have?

This list has 31 BACnet objects: 6 analog inputs, 2 analog outputs, 5 analog values, 4 binary inputs, 3 binary outputs, 3 binary values, 4 multi-state inputs, 3 multi-state outputs, 1 multi-state value. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Intesis INBACHIT001R000 (Hitachi VRF gateway) BACnet points are writable?

12 of the 31 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Intesis INBACHIT001R000 (Hitachi VRF gateway) BACnet documentation?

The source is Intesis BACnet IP/MSTP - Hitachi VRF User Manual (INBACHIT001R000), revision 09/2024 v1.4, published free by Intesis at https://www.hms-networks.com/docs/default-source/products/intesis/manuals-and-guides---manuals/user-manual-inbachit001r000-r1-0-en.pdf.

What are the minimum BACnet points to integrate the Intesis INBACHIT001R000 (Hitachi VRF gateway)?

Start with BO 0 OnOff_command (Start/stop the indoor unit); BI 0 OnOff_status (Confirm the unit is running); MO 0 Mode_command (Heat/cool/fan/dry/auto selection); AO 0 SetPoint_command (Temperature setpoint from the BMS); AI 0 SetPoint_status (Setpoint the unit is really using); AI 1 RoomTemperature_status (Room/return temperature for trending); AO 1 RoomTemperature_command (Feed a BMS room sensor (virtual temperature)); MO 1 FanSpeed_command (Fan speed selection); BI 1 ErrorActive (Unit alarm); AI 2 ErrorCode (Which fault is active).

How do I enable BMS control of the Intesis INBACHIT001R000 (Hitachi VRF gateway)?

No enable point or BMS/local switch is documented; the gateway accepts BACnet commands as soon as it is communicating with the unit. A wired remote controller can still be used in parallel; BV 2 LockRemoteControl locks it.

Can the BMS supply sensor values to the Intesis INBACHIT001R000 (Hitachi VRF gateway)?

Write a BMS room temperature to AO 1 RoomTemperature_command. BI 14 VirtualTempActive shows whether the gateway is using it, and AI 17 UserSetPoint_status shows the user setpoint written from BACnet while it is active (AI 0 then shows the setpoint actually applied).
