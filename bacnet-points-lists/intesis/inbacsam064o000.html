BMS integration notes: Intesis INBACSAM004O000 / 008O000 / 016O000 / 064O000 (Samsung NASA BACnet server)

Integration in brief

Connect the NASA R1/R2 bus to Port A (A3 R1/+, A4 R2/-), scan the bus in Intesis MAPS, assign each unit an identifier and send the project; then map each indoor unit's objects from its (identifier x 100) block. Gateway-wide objects at low instances command all units.

Enable & remote start

No enable point is documented. OxxUxx_RC Restriction_C (BO 103) restricts the unit's remote controller.

Network setup

  • Default device instance 246, configurable in MAPS.
  • BACnet IP: default IP 192.168.100.246, DHCP enabled by default.
  • Indoor units are addressed 0-63 and outdoor units 0-15 on the NASA bus; the identifier xxx (1-64) used in instance numbers is assigned in MAPS.

Watch out for

  • Mode state numbering is Samsung's: 1=Heat, 2=Dry, 3=Fan, 4=Cool, 5=Auto (not the usual Intesis order).
  • Check the Unit type object (MI 103) before mapping: other unit types use different objects in the same block.
  • Manual addressing may be needed on the outdoor units if BI 16 OU Addressing Error is active.

Integration notes

  • Indoor unit instance = (xxx x 100) + offset, xxx = indoor unit identifier 1-64 (identifier 1 shown, 100-108).
  • Outdoor communication-error objects are BI 0-15 for outdoor addresses 00-15; BI 16 flags an addressing problem.
  • Hot-water, AHU, ERV, ERV+ and chiller units reuse the same instance block with a different object set (see manual).
  • WindFree, Air Clean and 360 CST Air Flow objects apply only to indoor units that support them.
  • Communication Status (MI) states combine NASA flags such as RDY, EXST and DTUP.
