Short answer

With software 4.X the applied rooftop SmartVu controller publishes a network points list of 129 analog values (configurations, setpoints, BACnet-specific points such as air source linkage and schedule objects, sensors and status) plus 231 binary values in a separate alarm list (one BV per alarm code, with alarm reset and alarm activate). BMS integration notes: Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points)

Integration in brief

Set the J7/J8 serial port (MS/TP) or the IP settings from the SmartVu touchscreen, reboot, then write the network occupancy point after every power cycle and keep network sensor inputs refreshed within the network input timeout. Map the operating mode, occupancy source and filter status, and poll the alarm BVs or Alarm Activate.

Enable & remote start

The network occupancy point must be written after every controller power cycle to set the unit occupied; otherwise it defaults to not used, which leaves the unit unoccupied. It does not time out and keeps its last value if communication is lost.

Heartbeat & communication loss

Network inputs must be written at least every 10 minutes (service configurable) and after a power cycle; if no write arrives, the unit falls back to its local sensor value if one exists.

Sensors & values from the BMS

Sensor values can come from network points (including airside linkage); the touchscreen hides a sensor when its local input is disabled unless set to show it.

Network setup

  • J7 can be CCN or BACnet MS/TP (factory wired to the CCN comm board); J8 can be BACnet MS/TP or Rnet.
  • Only one BAS protocol (CCN or BACnet) at a time; most configuration changes need a reboot.
  • Excel versions of the network points are in the software download file on HVACPartners.

Watch out for

  • Software versions before 2.4.0 use different point instances and names; confirm the controller software version first.
  • The 4.X list differs from earlier SmartVu lists; do not reuse an older point map without checking instances.

Questions about the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points)

How many BACnet points does the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points) have?

This list has 360 BACnet objects: 129 analog values, 231 binary values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points) BACnet points are writable?

56 of the 360 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points) BACnet documentation?

The source is Applied Rooftop Units with PIC 6.1 Hardware and SmartVu Controls Version 4.X - Integration Guide (Appendix A, BACnet and CCN Network Points; Appendix B, Alarms List) (48-50-ART-SMVU-3T), revision 2026-09, published free by Carrier at https://brandportal.carrier.com/asset/2e92f64c-8801-4bec-9223-b684911196bf/48-50-ART-SMVU-3T.pdf.

What are the minimum BACnet points to integrate the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points)?

Start with AV 363 GENUNIT_NETOCC (Network occupancy command (rewrite after power cycle)); AV 366 OCCSBNET (Network occupied standby command); AV 291 MDESTS_OP_STATE (Operating mode (free, mech, staged, heating, dehum...)); AV 731 STATES_OCCSRNUM (Occupancy source in effect (local, BMS, remote...)); AV 727 STATES_IDFNUM (Indoor fan state); AV 297 FILTER_STATUS (Pre-filter status: 0=Clean, 1=Dirty); BV 8094 ALARMRST_ALM_ACT (Alarm active); BV 1 ALARMRST_RST_ALM (Alarm reset command).

How do I enable BMS control of the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points)?

The network occupancy point must be written after every controller power cycle to set the unit occupied; otherwise it defaults to not used, which leaves the unit unoccupied. It does not time out and keeps its last value if communication is lost.

Does the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points) need a BACnet heartbeat or have a communication timeout?

Network inputs must be written at least every 10 minutes (service configurable) and after a power cycle; if no write arrives, the unit falls back to its local sensor value if one exists.

Can the BMS supply sensor values to the Carrier 48/50K and 48/50V Applied Rooftop (SmartVu software 4.X network points)?

Sensor values can come from network points (including airside linkage); the touchscreen hides a sensor when its local input is disabled unless set to show it.
