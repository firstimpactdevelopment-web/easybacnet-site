Updated 28 October 2026

Short answer

The RDY2000BN is a touchscreen commercial thermostat with BACnet MS/TP built in. It stages up to three cooling and three heating stages from its relays, has four configurable inputs and three configurable auxiliary outputs, and holds its own weekly schedule. The conventional (14900) and heat pump (14901) applications expose the same 136 objects; SystemType selects between them.

BMS integration notes: Siemens RDY2000BN BACnet Commercial Thermostat (Applications 14900 / 14901)

Integration in brief

Set the MS/TP MAC address and baud rate, then command the system mode with HeatCoolMode (MV 23) and occupancy with SchedMode (MV 24), and adjust the comfort setpoints. Read the effective mode, room operating mode and IndoorTmpEff for status, and ExtFault and OverCurrent for alarms. Write at a priority higher than 16.

Enable & remote start

HeatCoolMode (MV 23) is the system mode command; its factory Relinquish_Default is Off, so the unit will not heat or cool until it is commanded or the default is changed. SchedMode (MV 24) sets Comfort, Economy or Protect; the internal schedule writes it too, and an occupancy input forces Comfort.

Sensors & values from the BMS

A universal input can be set as a voltage input, taken out of service and written from the network, so a BMS value can stand in for a physical sensor (for example IndoorTmpRmt with Input1-4 = InTemRem). IndoorTmpEff then uses that value alone or averaged with the built-in sensor.

Network setup

  • BACnet MS/TP only. MS/TP MAC (AV 38) ships at 255; BaudRate (MV 19) defaults to Auto.
  • Device instance defaults to 4194303.
  • To switch between conventional and heat pump, write SystemType (MV 3), not the APPLICATION value.
  • The weekly schedule can be edited from the BMS through the Weekly_Schedule property of Schedule 0; this sets the local scheduler to 7-day mode.

Watch out for

  • Factory HeatCoolMode default is Off; set it or the thermostat stays off.
  • Command at a priority from 1 to 15; the thermostat itself writes at 16.
  • Exception schedules are not supported; Niagara users must set those schedule properties to Skip Write before writing back.
  • If total relay current exceeds 3 A, all relays turn off for four minutes and OverCurrent (BV 25) turns on.
  • Setpoints, timers and configuration AVs are writable but are setup values; don't write them cyclically.

Integration notes

  • Points list is taken from the conventional application note (14900). The heat pump note (14901) lists the same objects; it differs only in some defaults and ranges (for example HeatStg and CoolStg 0-2, O/B default 1, SystemType default HEAT P).
  • Read-only inputs and status values (access R) can still be written after setting Out_Of_Service, which is how a network value replaces a universal input.
  • The thermostat commands its own outputs and command objects at priority 16; the BMS must write at a higher priority to override.
  • Temperatures follow the Units setting (°F or °C); °F is shown here.
  • The 14900 table marks HrsOvrRide, HpCompLock, HpAuxLock and the two lockout flags as present but with no effect on the conventional sequence.

Which Siemens RDY2000BN BACnet Commercial Thermostat (Applications 14900 / 14901) BACnet points are writable?

87 of the 136 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.
