Short answer

Older Systemair Access controllers (software 4.x) are native BACnet devices; Systemair publishes their objects as an EDE file set with state texts and units. Unlike 5.x, this release maps nearly everything to analog, binary and multistate values (1,050 objects) in numbered blocks: 10000s for commands, 20000s for alarms, 30000s for settings and 40000s for actual values, plus seven schedules (fan speeds and four extra time channels), a holiday calendar and three notification classes. Physical inputs appear as AVs/BVs named AI_ and DI_.

This page lists 1050 BACnet objects for the Systemair Access controller 4.x (4.7) BACnet — 362 of them writable — with each object’s type, instance number, name, engineering units and access. It is re-typed from Systemair’s own free documentation, linked below.

BMS integration notes: Systemair Access controller 4.x (4.7) BACnet

Integration in brief

Use MV-30565 AirUnitAutoMode (AUTO = 3, or force low/normal/high speed) as the BMS run command, or MV-30573 ExternalControl for extended run / external stop. Read MV-40396 UnitMode and MV-40397 UnitModeControl for the actual mode and its cause, map supply/extract temperatures and AV-30588 SupplySetpoint, and use BV-20007..20010 sum alarms with BV-10000 to acknowledge all alarms. A BMS outdoor temperature can be written to AV-30850.

Enable & remote start

MV-30565 AirUnitAutoMode: 1=OFF, 2=Manual (state chosen in MV-30566), 3=AUTO, 4=Low, 5=Normal, 6=High speed. MV-30573 ExternalControl gives extended run speeds 1-3 and external stop; MV-30574 AirUnitServiceStop stops the unit with top priority.

Sensors & values from the BMS

AV-30850 BMS_OutDoorTemp accepts an outdoor temperature from the BMS. BV-20196 CommunicationFaultBMS alarms on a BMS master communication fault; the files give no timeout.

Network setup

  • Device ID and name are set in the controller (placeholders in the EDE); the ID must be unique on the network.
  • Per the Access 4.x communication manual, BACnet/IP is disabled on delivery and must be enabled in the communication settings; a BBMD address (default port 47808) turns the controller into a foreign device.
  • BACnet support started at 4.0-1-05 (ASC profile); the AAC profile came with 4.3-1-00 (Access 4.x manual).

Watch out for

  • Object instances are large block numbers (10000/20000/30000/40000 ranges), not sequential.
  • Physical sensor readings are AVs (AI_ prefix), not AI objects.
  • Settings AVs (30000 range) are configuration settings.
  • Multistate states start at 1, so AUTO on MV-30565 is 3.

Integration notes

  • Access comes from the EDE settable column (Y = writable); schedules and the calendar are left as writable.
  • The device instance and name are placeholders (@DeviceID, @DeviceName) in the EDE, set per controller.
  • Several feedback AVs are marked 'Not valid in version 4.4' in their descriptions.
  • Many temperature and pressure AVs carry BACnet units NO-UNITS; temperatures are °C.
  • The EDE does not name the data link; Systemair's Access communication manual (153831) describes BACnet/IP via the TCP/IP port (ASC profile from 4.0-1-05, AAC from 4.3-1-00).
  • A matching Access 4.7-1-00 variable list (Excel) is in the same download.

Questions about the Systemair Access controller 4.x (4.7) BACnet

How many BACnet points does the Systemair Access controller 4.x (4.7) BACnet have?

This list has 1050 BACnet objects: 673 analog values, 295 binary values, 1 calendar, 3 notification classs, 7 schedules, 71 multi-state values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Systemair Access controller 4.x (4.7) BACnet BACnet points are writable?

362 of the 1050 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done.

Where is the official Systemair Access controller 4.x (4.7) BACnet BACnet documentation?

The source is Access 4.x Modbus variables and BACnet objects (BACnet object files Access 4.7-1-02 build 78: EDE, state texts, units) (4.7-1-02 build 78), revision 2022-12-14, published free by Systemair at https://systemair.canto.global/direct/other/092hjedtn543je5ivo9m2njh4m/CM9llsIhUF7VaB-6eOjGXK_g-y8/original?content-type=application%2Fzip&name=Access+4.x+Modbus+variables+and+BACnet+objects.zip.

What are the minimum BACnet points to integrate the Systemair Access controller 4.x (4.7) BACnet?

Start with MV 30565 AirUnitAutoMode (Off / manual / auto / forced speed command); MV 30573 ExternalControl (External extended run or stop command); AV 30588 SupplySetpoint (Supply air temperature setpoint); BV 10000 AlaAcknowAll (Acknowledge all alarms); MV 40396 UnitMode (Actual run mode); MV 40397 UnitModeControl (What is driving the current run mode); AV 40292 AI_SupplyAirTemp (Supply air temperature); AV 40294 AI_ExtractAirTemp (Extract air temperature); AV 40290 AI_OutDoorTemp (Outdoor temperature); BV 20007 SumAlarm (Any alarm).

How do I enable BMS control of the Systemair Access controller 4.x (4.7) BACnet?

MV-30565 AirUnitAutoMode: 1=OFF, 2=Manual (state chosen in MV-30566), 3=AUTO, 4=Low, 5=Normal, 6=High speed. MV-30573 ExternalControl gives extended run speeds 1-3 and external stop; MV-30574 AirUnitServiceStop stops the unit with top priority.

Can the BMS supply sensor values to the Systemair Access controller 4.x (4.7) BACnet?

AV-30850 BMS_OutDoorTemp accepts an outdoor temperature from the BMS. BV-20196 CommunicationFaultBMS alarms on a BMS master communication fault; the files give no timeout.
