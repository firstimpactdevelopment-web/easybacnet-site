Short answer

Systemair's Access controller, fitted to its larger air handling units, is a native BACnet device; Systemair publishes its object list as an EDE file set (objects, state texts, units) rather than a PDF table. The 1,201 objects cover run-mode commands and settings (S_ variables), actual values and I/O (A_ variables), fan and damper data from the Modbus-connected motors (CA_ variables), alarms (AL_), trend logs, schedules, a calendar and notification classes. One application covers many unit types, so most objects only matter when the matching function is configured.

BMS integration notes: Systemair Access controller 5.x (ControllerProgram) BACnet

Integration in brief

Set MV-12 AirUnitAutoMode to AUTO (3) to let the unit follow its schedule, or to Low/Normal/High speed to force it; MV-31 ExternalControl gives BMS-style extended run and stop commands. Read MV-15 UnitMode and MV-16 UnitModeControl to see what the unit is doing and why, map the supply/extract temperatures and supply setpoint, and watch BV-9..12 sum alarms with BV-8 to acknowledge all alarms. Outdoor temperature and summer/winter or changeover modes can be supplied by the BMS through the BMS_ objects.

Enable & remote start

MV-12 AirUnitAutoMode: 1=OFF, 2=Manual (uses MV-13 AirUnitManual), 3=AUTO, 4=Low speed, 5=Normal speed, 6=High speed. MV-31 ExternalControl adds extended run low/normal/high, external stop, start free cooling and recirculation. MV-32 AirUnitServiceStop stops the unit with top priority.

Sensors & values from the BMS

AV-466 BMS_OutDoorTemp takes an outdoor temperature from BACnet/Modbus; BV-156 BMS_SummerMode and BV-157/158 BMS_ChangeOver1/2 take summer/winter and cooling/heating changeover modes. BV-51 CommunicationFaultBmsMaster is an alarm for a BMS master communication fault; the files do not state its timeout.

Network setup

  • The published EDE uses device instance 114112 (device name Access); the device ID must be unique on the network.
  • Per the Access 4.x communication manual, BACnet/IP is disabled on delivery and must be switched on in the controller's communication settings.
  • Entering a BBMD address (host:port, default port 47808) makes Access a BACnet/IP foreign device that ignores other broadcasts (Access 4.x manual).
  • Systemair supplies EDE, object-type, state-text and unit files plus a Modbus cross-reference in one zip per Access release; use the one matching the controller's software.
  • The Modbus cross-reference in the same package shows Modbus TCP enabled with device address 1.

Watch out for

  • Access is inferred: the EDE marks every object as not settable, so confirm writes on site.
  • Many temperature and pressure objects report BACnet units NO-UNITS even though values are °C or Pa.
  • S_ setting objects (PID bands, curves, limits) are configuration settings.
  • Multistate states start at 1 in BACnet, so 'AUTO' on MV-12 is value 3.

Integration notes

  • The EDE settable column is 'N' for every object, so access is inferred: S_ (setting) objects and the A_BMS_ inputs are shown writable, everything else read-only.
  • State texts come from the EDE state-text table; multistate values are numbered from 1.
  • Most temperature, pressure and airflow objects carry BACnet unit NO-UNITS in the EDE, so their units are blank here (temperatures are °C).
  • Device instance 114112 is the one in the published EDE; set a unique value per unit.
  • Sequences A-J, zones 1-4, heat pump (HP) and up to 10 supply/extract fan motors are generic slots; only configured ones carry data.
  • The EDE does not name the data link; Systemair's Access 5 communication manual (472956) describes BACnet/IP on the B-BC profile from 5.0-1-00.

How many BACnet points does the Systemair Access controller 5.x (ControllerProgram) BACnet have?

This list has 1201 BACnet objects: 59 analog inputs, 27 analog outputs, 545 analog values, 87 binary inputs, 78 binary outputs, 152 binary values, 1 calendar, 1 device, 4 notification classs, 5 schedules, 87 multi-state values, 96 trend logs, 5 integer values, 54 positive integer values. The exact set on a given unit depends on its firmware, installed options and configuration.

Which Systemair Access controller 5.x (ControllerProgram) BACnet BACnet points are writable?

348 of the 1201 objects accept a write. Points marked Command have a priority array: a write holds until it is released, so release it back to automatic when you are done. The source has no read/write column, so this is inferred from object type.

What are the minimum BACnet points to integrate the Systemair Access controller 5.x (ControllerProgram) BACnet?

Start with MV 12 AirUnitAutoMode (Off / manual / auto / forced speed command); MV 31 ExternalControl (External extended run or stop command); AV 39 SupplySetpoint (Supply air temperature setpoint); BV 8 AlaAcknowAll (Acknowledge all alarms); MV 15 UnitMode (Actual run mode); MV 16 UnitModeControl (What is driving the current run mode); AI 3 AI_SupplyAirTemp (Supply air temperature); AI 5 AI_ExtractAirTemp (Extract air temperature); AI 1 AI_OutDoorTemp (Outdoor temperature); BV 9 SumAlarm (Any alarm).

How do I enable BMS control of the Systemair Access controller 5.x (ControllerProgram) BACnet?

MV-12 AirUnitAutoMode: 1=OFF, 2=Manual (uses MV-13 AirUnitManual), 3=AUTO, 4=Low speed, 5=Normal speed, 6=High speed. MV-31 ExternalControl adds extended run low/normal/high, external stop, start free cooling and recirculation. MV-32 AirUnitServiceStop stops the unit with top priority.

Can the BMS supply sensor values to the Systemair Access controller 5.x (ControllerProgram) BACnet?

AV-466 BMS_OutDoorTemp takes an outdoor temperature from BACnet/Modbus; BV-156 BMS_SummerMode and BV-157/158 BMS_ChangeOver1/2 take summer/winter and cooling/heating changeover modes. BV-51 CommunicationFaultBmsMaster is an alarm for a BMS master communication fault; the files do not state its timeout.
